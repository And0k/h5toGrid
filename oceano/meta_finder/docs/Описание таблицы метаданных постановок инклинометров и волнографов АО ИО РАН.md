
Таблица получена по файлу ( `*_meta_TCM.tsv`), созданному программой **meta_finder** в результате сканирования директорий экспедиций и последующего небольшого ручного редактирования. Данные содержат консолидированные метаданные обо всех обнаруженных устройствах (инклинометрах и волнографах) и их данных.
Ниже приведено подробное описание каждой колонки и происхождения данных.

## 1.2. Подробное описание колонок и происхождение данных
#### `setup_name` — Имя набора данных (экспедиция + дата + устройство)
- **Источник:** формируется автоматически из имени каталога экспедиции функцией [`add_dataset_name()`](../src/meta_finder/parse_cruise_dir_name.py:159) по **алгоритму:**
  1. Из имени каталога cruise-директории (вида `YYMMDD_название`) удаляется дата и суффиксы, связанные с устройствами (ключевые слова `inclinometer`, `wavegauge` и т.д., а также идентификаторы приборов после `@`, `#`).
  2. Если получившееся имя не содержит цифр, используется разделитель `/` между датой и названием: `1305/Sambian`.
  3. Если имя содержит цифры (номер рейса), разделитель `_`: `171017_ANS36`, `230616Kulikovo`
  4. При совпадении имён разных экспедиций добавляются дополнительные компоненты даты (YYMM или YYMMDD) для обеспечения уникальности.
#### `device_id` — Идентификатор прибора
- **Источник:** извлекается из нескольких источников в порядке приоритета:
  1. Из имени файла данных в `text_output/` (функция [`parse_filename_for_metadata()`](../src/meta_finder/parse_data_file_name.py)).
  2. Из содержимого файла данных (имена колонок) при наличии обобщённых типов (`*`, `i`, `w`, `p`).
  3. Из имени подкаталога внутри `text_output/` (функция `_extract_device_id_from_subdirectory_name()`).
  4. Из файлов в каталоге `_raw/`.
  5. Из групп HDF5-файлов.
- **Формат:** нормализованный идентификатор: тип + модель + номер. Ведущие нули и подчёркивания удаляются.
  - `i3` — инклинометр №3
  - `w1` — волнограф №1 (может содержать колонки данных инклинометров, но использование в качестве инклинометра не предполагается)
  - `ib27` — инклинометр модели `b` №27
  - `ip6` — инклинометр  модели `p` (с датчиком давления "pressure") №6
- **Нормализация:** выполняется функцией [`normalize_device_id()`](../src/meta_finder/parse_data_file_name.py); `i_03` → `i3`, `i_b27` → `ib27`, `W01` → `w1`.

#### `point` — Название/номер станции
- **Источник:** поле `point` (индекс 0) из информационного файла ([`info_devices*.yaml или *.json`](../src/meta_finder/config.py:17) из каталога прибора), значение по умолчанию: `?`.

#### `sea_depth` — Глубина моря
- **Источник:** поле `sea_depth` (индекс 1) из информационного файла, значение по умолчанию: `?`.
- **Единицы:** метры.

#### `height_above_bottom` — Высота прибора над дном
- **Источник:** поле `height_above_bottom` (индекс 2) из информационного файла, значение по умолчанию: `?`.
- **Единицы:** метры.

#### `modification_symbol` — Символ модификации/конструкции
- **Источник:** поле `modification_symbol` (индекс 3) из информационного файла, значение по умолчанию: `?`.
- **Примеры** :
  - `⯯` — отрицательная плавучесть (самый широкий диапазон)
  - `⯭` — положительная плавучесть, широкий диапазон (с большим поплавком)
  - `⭡` — положительная плавучесть, узкий диапазон измеряемой скорости течения
  - `⤉` — положительная плавучесть, со штангой
#### `lat` — Широта
- **Источник:** поле `lat` (индекс 4) из информационного файла, значение по умолчанию: `?`.
- **Формат:** градусы (десятичные).

#### `lon` — Долгота
- **Источник:** поле `lon` (индекс 5) из информационного файла, значение по умолчанию: `?`.
- **Формат:** градусы (десятичные).

#### `time_st` — Время начала обработанных данных
- **Источник (в порядке приоритета):**
  1. Из информационного файла (поле `time_st`, индекс 6), если также не извлечено из данных, то значение по умолчанию: `?`.
  2. Из текстового файла данных (функция [`extract_time_info_from_text_file()`](../src/meta_finder/data_proc_funcs.py)) — чтение первой и последней строк данных.
  3. Из HDF5-файла (функция [`extract_time_range_from_hdf5_table()`](../src/meta_finder/hdf5_processor.py)) при включённой опции `extract_hdf5_times`.
- **Формат:** `YYYY-MM-DD HH:MM:SS`.

#### `time_en` — Время конца обработанных данных
- **Источник:** аналогичен `time_st` (индекс 7 в информационном файле), если также не извлечено из данных, то значение по умолчанию: `?`.
- **Формат:** `YYYY-MM-DD HH:MM:SS`.

#### `burst_dt` — Интервал активности прибора
- **Источник:**
  1. Поле `burst_dt` (индекс 8) из информационного файла, если также не извлечено из данных, то значение по умолчанию: `-`: означает, что прибор работал непрерывно (без периодического выключения), либо данные о burst-режиме отсутствуют.
  2. Вычисляется при извлечении временных данных из текстовых файлов: если задан интервал осреднения (averaging_interval, анализируются разрывы в метках времени для определения параметров burst-режима).
- **Единицы:** секунды.

#### `bursts_t` — Период работы прибора
- **Источник:**
  1. Поле `bursts_t` (индекс 9) из информационного файла, если также не извлечено из данных, то значение по умолчанию: `-` — аналогично `burst_dt`.
- **Единицы:** секунды.

#### `data_file_path` / `data_paths` — Путь(и) к файлу(ам) данных
- **Источник:** формируется из обнаруженных файлов данных для каждого прибора, еслифайлы данных не обнаружены, то значение по умолчанию: `?`.
- **Режим по умолчанию** (`data_file_path`): записывается один путь — к файлу данных наивысшего приоритета (см. раздел «Приоритеты источников данных»).
- **Расширенный режим** (`data_paths`, при флаге `--write-all-collected-paths`): записываются все обнаруженные пути к файлам данных через запятую не использовался.

#### `quality` — Индикатор качества источника данных
**Источник:** Пользовательская оценка данных (вручную). По умолчаниювычисляется на основе пути к файлу данных в [`write_metadata_table()`](../src/meta_finder/file_writer.py:244) значениями:
  - `+` — данные из обработанного файла (text_output, .proc.h5 и т.п.; путь **не содержит** `_raw`).
  - `-` — файл данных не обнаружен (путь = `?`).
  - `?` — данные из «сырого» источника (путь содержит `_raw`).
Если данные амплитуды и направления можно оценить по разному, то сначала идет оценка амплитуды, потом направления (например "+-"). Если прибор измерял и давление и скорость, то давление не оценивалось.

#### `comment` — Комментарий
- **Источник (комбинируются через `;`, значение по умолчанию: пустая строка):**
	- Поле `comment` (индекс 10) из информационного файла — пользовательский комментарий.
	- Если в качестве источника данных выбраны **комбинированные файлы** (в которых столбец данных составлен из последовательных данных от нескольких приборов (заголовок типа `Vabs_i05_14`)), то программа могла добавить комментарий вида `{device1}+{device2} output`. - не случалось, т.к. находились по приоритету одиночные файлы.

#### `coef_date` — Дата калибровочных коэффициентов
- **Источник:** извлекается из HDF5-файлов в каталоге `_raw/` (группа `coef`) при включённой опции `extract_hdf5_coef_dates` или при наличии `coef_date` в `raw_hdf5_cols`, значение по умолчанию: `?`.
- **Формат:** `YYYY-MM-DD HH:MM:SS`.

#### `time_raw_st` — Начало «сырых» данных
- **Источник:** извлекается из файлов в каталоге `_raw/`, значение по умолчанию: `?`.
- **Формат:** `YYYY-MM-DD HH:MM:SS`.

#### `time_raw_en` — Конец «сырых» данных
- **Источник:** аналогичен `time_raw_st`.
- **Формат:** `YYYY-MM-DD HH:MM:SS`.

### 1.3. Приоритеты источников данных

Система приоритетов определяет, из какого файла извлекаются временные данные (`time_st`, `time_en`, `burst_dt`, `bursts_t`) для каждого прибора. Сортировка выполняется функцией [`sort_data_paths()`](../src/meta_finder/data_processor.py:87).

**Трёхуровневая схема приоритетов:**

| Приоритет | Уровень | Описание |
|-----------|---------|----------|
| **1-й уровень** | Обработанные vs «сырые» | Обработанные данные (`text_output`, `.proc.h5`) имеют приоритет над «сырыми» (`_raw/`, raw `.h5`/`.mat`). |
| **2-й уровень** | Интервал осреднения | Оптимальное значение — 2 с. Приоритет снижается при удалении от 2 с в обе стороны (как в большую — 300 с, так и в меньшую). Для HDF5-файлов осреднение ≤ 2 с приравнивается к 2 с. Файлы без указания осреднения получают значение по умолчанию 2.0001 с (чуть ниже приоритетом, чем 2 с). |
| **3-й уровень** | Тип источника | Среди файлов одного уровня: каталоги > архивы (.zip/.7z) > proc_noAvg.h5 > proc_Avg.h5 > proc.h5 > raw .h5 > .mat. |
**Дополнительные критерии для разрешения совпадений:**

| Приоритет | Критерий                     | Описание                                                                    |
| --------- | ---------------------------- | --------------------------------------------------------------------------- |
| **4-й**   | Специфичность                | Файлы для конкретных приборов приоритетнее комбинированных                  |
| **5-й**   | Число приборов               | Файлы с меньшим числом приборов в имени приоритетнее.                       |
| **6-й**   | Число несовпадающих приборов | Файлы с меньшим числом приборов, не входящих в целевой набор, приоритетнее. |

### 1.4. Условные обозначения и placeholder-значения
**Политика сохранения данных:** при объединении метаданных из информационных файлов, данные из последних приоритетнее (значения (`?`, `""`, `None`, `-`) не считаются, см. функцию [`_update_time_fields()`](../src/meta_finder/collect.py:217)).

### 1.5. Множественные интервалы (multi-interval devices)
Если прибор имеет несколько интервалов постановки (например, поднят и повторно установлен), в информационном файле используется вложенная структура:

```yaml
i03:
  0: [P1, 15, 0.5, ?, 54.7, 19.8, "2023-05-08 12:00:00", "2023-05-15 08:00:00", -, -, ""]
  1: [P2, 20, 1.0, ?, 54.9, 20.1, "2023-06-01 10:00:00", "2023-06-10 14:00:00", 120, 600, ""]
```

В этом случае в TSV-файле создаётся **отдельная строка для каждого интервала**. Ключ интервала (в примере `0`, `1`, соответствует названию постановки: по умолчанию - порядковому номеру начиная с 0)

### 1.6. Сортировка строк
Строки в таблице сортируются по дате набора данных (из имени каталога прибора или экспедиции, функция [`parse_dated_dir()`](../src/meta_finder/parse_cruise_dir_name.py:25)) в порядке возрастания. Внутри одной экспедиции порядок определяется порядком устройств в информационном файле.

## 2. Структура каталогов данных
Программа ожидает следующую стандартную структуру каталогов:
```
B:/WorkData/BalticSea/
└── YYMMDD_{название_экспедиции}/
    ├── *inclinometer* или *wavegauge*/
    │   ├── info_devices@meta_finder.yaml  ← приоритет 1 (генерируется автоматически, если находятся данные отсутствующие в info_devices.yaml)
    │   ├── info_devices.yaml              ← приоритет 2
    │   ├── info_devices.json              ← приоритет 3 (устаревший)
    │   ├── text_output/
    │   │   └── *.tsv, *.txt, *.csv        ← обработанные текстовые данные
    │   ├── text_output.zip                ← альтернатива: архив текстовых данных
    │   ├── text_output.7z
    │   ├── *.proc_noAvg.h5               ← обработанные HDF5 без осреднения
    │   ├── *.proc.h5                     ← обработанные HDF5 с осреднением
    │   ├── *.proc_Avg.h5                 ← обработанные HDF5 (группы по приборам)
    │   └── _raw/
    │       ├── *.h5, *.mat               ← «сырые» данные
    │       └── *.txt, *.tsv, *.csv       ← «сырые» текстовые данные
    └── *navigation* или *map*/
        └── *.gpx                         ← навигационные файлы
```

Также поддерживаются комбинированные структуры:
- `YYMMDD{название}/{device_type}/info_devices.yaml`
- `YYMMDD{название}/info_devices.yaml` (метаданные в корне)
- `YYMMDD{название}/inclinometers/{YYMMDD}*/info_devices.yaml` (вложенные датированные подкаталоги)
Вместо `YYMMDD` может быть `YYMM` или  `YYMM..YYMM` (для даты данных берутся только первые цифры, из {названия} удаляется префикс из цифр и разделителей)

## 5. Имена файлов данных и извлечение идентификаторов приборов

### 5.1. Поддерживаемые шаблоны имён файлов

| Шаблон | Пример | Извлечённые данные |
|--------|--------|--------------------|
| `{datetime}bin{interval}s[@_#]{devices}.tsv` | `191108_1200bin600s@i03.tsv` | devices: i03, bin: 600s |
| `{date}#{devices}-bin{interval}s.{ext}` | `191210#07,23,30,32-bin300s.zip` | devices: i07,i23,i30,i32, bin: 300s |
| `{date}#{devices}.{ext}` | `191210#i03.tsv` | devices: i03 |
| `{date}_{time}_{device}.{ext}` | `200113_0000_i13.csv` | device: i13 |
| `{date}_{time}@{device}.{ext}` | `200113_00@i13.csv` | device: i13 |

### 5.2. Сложные шаблоны идентификаторов

- **Точка с запятой** разделяет группы приборов: `i3,4,15;ib27-30,ip6.tsv`
- **Диапазоны** расширяются: `27-30` → `27, 28, 29, 30`
- **Скобки:** `i(38,37,59,60,58).tsv` → `i38,i37,i59,i60,i58`

### 5.3. Нормализация идентификаторов

| Исходное | Нормализованное | Примечание |
|----------|----------------|------------|
| `i_03` | `i03` | Удаляется подчёркивание после типа |
| `i_b27` | `ib27` | Удаляется подчёркивание между типом и моделью |
| `i_p06` | `ip06` | Аналогично |
| `W1` | `w1` | Приведение к нижнему регистру |
| `INCL01` | `i01` | Развёрнутая форма типа сокращается |
| `i03_` | `i03_` | Подчёркивание на конце **не** удаляется (дополнительная запись) |

### 6.1. Формат информационного файла

## 3. Информационные файлы — источники метаданных

Данные в колонки `meta_TCM.tsv` попадают из информационных файлов, которые ищутся в следующем порядке приоритета (функция [`read_metadata_files()`](../src/meta_finder/metadata_extractor.py:55)):

| Приоритет  | Имя файла                       | Формат | Описание                                             |
| ---------- | ------------------------------- | ------ | ---------------------------------------------------- |
| 1 (высший) | `info_devices@meta_finder.yaml` | YAML   | Файл, создаваемый/обновляемый программой meta_finder |
| 2          | `info_devices.yaml`             | YAML   | Пользовательский файл метаданных                     |
| 3 (низший) | `info_devices.json`             | JSON   | Устаревший формат                                    |

Файл содержит структуру `device_id: [массив]` (или вложенную структуру для множественных интервалов):

```yaml
# Instrument_ID: [Point, Sea_depth, H_above_bot, Symbol, Lat, Lon, Time_st, Time_en, Burst_dt, Bursts_t, Comment]
i03: ["P1", 15, 0.5, "⯯", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
w01: ["P1", 15, 5, "", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
```

**Порядок элементов массива** (определяется константой [`info_devices_field_names_extended`](../src/meta_finder/io_info_files.py:37)):

| Индекс | Имя поля | Описание | Обязательный |
|--------|----------|----------|--------------|
| 0 | `point` | Название/номер станции | Да |
| 1 | `sea_depth` | Глубина моря (м) | Да |
| 2 | `height_above_bottom` | Высота прибора над дном (м) | Да |
| 3 | `modification_symbol` | Символ модификации | Да |
| 4 | `lat` | Широта (градусы) | Нет |
| 5 | `lon` | Долгота (градусы) | Нет |
| 6 | `time_st` | Время начала данных | Нет |
| 7 | `time_en` | Время конца данных | Нет |
| 8 | `burst_dt` | Интервал активности (с) | Нет |
| 9 | `bursts_t` | Период работы (с) | Нет |
| 10 | `comment` | Комментарий | Нет |
| 11 | `coef_date` | Дата калибровки (из HDF5) | Нет |
| 12 | `time_raw_st` | Начало raw-данных | Нет |
| 13 | `time_raw_en` | Конец raw-данных | Нет |

- **Минимальная длина массива:** 4 элемента (первые 4 обязательных поля).
- **Отсутствующие элементы** заполняются значениями по умолчанию: `?` для большинства полей, `""` — для `burst_dt`, `bursts_t`, `coef_date`, `time_raw_st`, `time_raw_en`.
- **Значения `null`/`~`** в YAML обрабатываются как отсутствующие.
- **Идентификаторы приборов с пробелом в начале** (например, `" i10"`) игнорируются — это соглашение о приборе, по которому данные ещё не собраны.

### 3.2. Форматы времени
Поля времени (`time_st`, `time_en`, `coef_date` и др.) принимают форматы ISO:

| Формат | Пример |
|--------|--------|
| `YYYY-MM-DD HH:MM:SS` | `2019-12-10 14:22:00` |
| `YYYY-MM-DDTHH:MM:SS` | `2019-12-10T14:22:00` |
| `YYYY-MM-DDTHH:MM` | `2019-12-10T14:22` |
| `YYYY-MM-DD HH:MM` | `2019-12-26 12:40` |
| `YYYY-MM-DDTHH:MM:SS.ffffff` | `2019-12-10T14:22:00.123456` |
Все форматы нормализуются к `YYYY-MM-DD HH:MM:SS` при чтении (функция [`info_meta_list_to_dict()`](../src/meta_finder/metadata_extractor.py:16)).

# Файл `{YYMMDD_HHMM}_files_TCM.tsv` — список файлов

### Формат

Файл представляет собой текстовый список путей, сгруппированных по экспедициям. Формируется функцией [`write_files_list()`](../src/meta_finder/file_writer.py:14).

**Структура:**

```
путь/к/каталогу/устройств/экспедиции1
путь/к/файлу/данных1.tsv
путь/к/файлу/данных2.tsv
...

путь/к/каталогу/устройств/экспедиции2
путь/к/файлу/данных3.tsv
...
```

### Описание содержимого

Для каждой экспедиции (cruise) записи формируются следующим образом:

1. **Первая строка группы** — путь к каталогу устройств (device directory) в POSIX-формате.
2. **Последующие строки** — пути к файлам данных для каждого прибора в этом каталоге.

**Порядок записей:**
- Экспедиции сортируются по дате (из `cruise_date_map`), затем по имени.
- Каталоги устройств внутри экспедиции сортируются по пути.
- Приборы внутри каталога сортируются по `device_id`.
- Файлы данных для каждого прибора сортируются по приоритету (как описано в разделе 1.3).

**Количество файлов на прибор:**
- По умолчанию: записывается **один** файл данных (наивысшего приоритета) для каждого прибора.
- При флаге `--write-all-collected-paths`: записываются **все** обнаруженные файлы данных для каждого прибора.

**Группы экспедиций разделены пустой строкой.**

### Типы включаемых файлов

В список включаются пути к файлам из следующих источников:

| Источник | Расширения | Описание |
|----------|------------|----------|
| `text_output/` (каталоги и архивы) | `.tsv`, `.txt`, `.csv` | Обработанные текстовые данные |
| `_raw/` | `.txt`, `.tsv`, `.csv`, `.h5`, `.hdf5`, `.mat` | «Сырые» данные прибора |
| HDF5 (корень device_dir) | `.h5` | Обработанные HDF5: `.proc_noAvg.h5`, `.proc.h5` |
| Подкаталоги с `h5` в имени | `.h5` | Дополнительные HDF5-файлы |
