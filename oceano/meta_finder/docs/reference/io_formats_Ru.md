# Спецификация форматов ввода/вывода

Авторитетные контракты для форматов данных, принимаемых и производимых meta_finder.
Реализация: [`file_finder.py`](../../src/meta_finder/file_finder.py) (обнаружение),
[`parse_data_file_name.py`](../../src/meta_finder/parse_data_file_name.py) (идентичность),
[`data_proc_funcs.py`](../../src/meta_finder/data_proc_funcs.py) (извлечение времени),
[`file_writer.py`](../../src/meta_finder/file_writer.py) (вывод).

## Входные форматы

### Текстовые файлы данных

Табуляция-разделённые текстовые файлы в директориях `text_output/` или архивах (`.zip`, `.7z`).

**Файлы данных инклинометра (tilt current meter) содержат следующие заголовочные столбцы данных (с tab-разделителем):**
- Time – Калининградское время, `yyyy-mm-dd HH:MM:SS.ffffff`, (в старых версиях столбец также может называться `index`)
- Vabs – абсолютное значение скорости течения, м/с
- Vdir – направление скорости течения, ° в географической системе координат
- v – северная компонента скорости течения, м/с
- u – восточная компонента скорости течения, м/с
- Inclination – угол наклона инклинометра, °
- Temp – температура процессора инклинометра, °C

**Файлы данных волнографов содержат следующие заголовочные столбцы данных (с tab-разделителем):**
- Time – Калининградское время, `yyyy-mm-dd HH:MM:SS.ffffff`
- Pressure – давление, dBar

**Файлы данных, объединяющие данные от нескольких устройств**, обычно содержат меньший набор столбцов для каждого устройства; столбцы данных имеют суффикс имени устройства. Пример:

```
index  v_i03  u_i03  Temp_i03  v_i04  u_i04  Temp_i04
```

### HDF5 и MAT файлы

MAT файлы (`.mat`) в директориях `_raw` обрабатываются так же, как HDF5 файлы с сырым приоритетом.

**Не .proc.h5 файлы содержат группы:**
- `device_id` (может быть нормализованным или нет, например, `i07`, `w01`, `inclinometer07`, `@i07`)
- `table` (таблица данных) со столбцами по именам параметров
- `coef` (только в файлах сырой директории или с суффиксом `.raw.h5`) - группа с коэффициентами и их метаданными

**.proc_noAvg.h5:**
```
/
├── i63/  # device_id_proc (нормализованное имя устройства)
│   ├── table (столбцы: ['index', 'v', 'u', 'inclination', 'Battery', 'Temp'])
│   └── logFiles/
│       └── table (столбцы: ['index', 'fileName', 'fileChangeTime', 'DateEnd', 'DateProc'])
```

**.raw.h5:**
```
/
├── incl63/  # device_id_raw (ненормализованное имя устройства)
│   ├── table (столбцы: ['index', 'Ax', 'Ay', 'Az', 'Mx', 'My', 'Mz', 'Battery', 'Temp'])
│   ├── coef/
│   └── logFiles/
│       └── table (столбцы: ['index', 'fileName', 'fileChangeTime', 'DateEnd', 'DateProc'])
```

**.proc.h5 файлы содержат группы:**
- averaging_bin (содержит информацию об осреднении в имени, например, `bin600s`)
- `table` (таблица данных) со столбцами параметров, содержащими суффиксы device_id

**.proc_Avg.h5 файлы содержат группы:**
- device_id с осреднением bin (например, `i04bin2s`, `i03bin600s`) - идентификаторы устройств в именах групп, а не в именах столбцов
- `table` (таблица данных) со столбцами имён параметров БЕЗ суффиксов device_id (столбцы типа "Vabs", "v", "u" и т.д.)

Структура примера:
```
/
├── i04bin2s/  # device_id с averaging bin
│   └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
├── i05bin2s/  # другое устройство с тем же осреднением
│   └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
└── i03bin600s/  # устройство с другим осреднением
    └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
```

## Анализ имён файлов

`parse_filename_for_metadata()` в [`parse_data_file_name.py`](../../src/meta_finder/parse_data_file_name.py) извлекает идентичность устройства из имён файлов.

### Поддерживаемые шаблоны имён файлов

| Шаблон | Пример | Извлечённые данные |
|---------|---------|--------------------|
| `{datetime}bin{interval}s[@_#]{devices}.tsv` | `191108_1200bin600s@i03.tsv` | devices: i03, bin: 600s |
| `{date}#{devices}-bin{interval}s.{ext}` | `191210#07,23,30,32-bin300s.zip` | devices: i07,i23,i30,i32, bin: 300s |
| `{date}#{devices}.{ext}` | `191210#i03.tsv` | devices: i03 |
| `{date}_{time}_{device}.{ext}` | `200113_0000_i13.csv` | device: i13 |
| `{date}_{time}@{device}.{ext}` | `200113_00@i13.csv` | device: i13 |

Любая часть кроме Date (которая может быть в формате `yymmdd_HHMM`, `yymmdd_HH` или `yymmdd`) может быть опущена. Разделитель: "@", "_" или "#". Секунды: интервал бина (float).

### Сложные шаблоны имён устройств

- **Точка с запятой** разделяет группы устройств: `i3,4,15,19,37,38;ib27-30,ip6.tsv`
- **Расширение диапазона**: `27-30` → `["27", "28", "29", "30"]`
- **Скобки**: `i(38,37,59,60,58).tsv` → `i38,i37,i59,i60,i58`
- **Смешанные префиксы**: `i_b(27,28,29,30).tsv` → устройства: `i_b27, i_b28, i_b29, i_b30`

### Нормализация идентификаторов устройств

Файлы данных обычно содержат имена устройств в имени файла, которое является аббревиатурой типа устройства, модели и номера. Подчёркивания после типа ("i" для инклинометра) или нули перед первым другим номером не считаются значимыми:

| Исходное | Нормализованное | Примечание |
|----------|----------------|------------|
| `i_b27` | `ib27` | Подчёркивание после типа удалено |
| `i_p06` | `ip06` | Подчёркивание между типом и моделью удалено |
| `i_03` | `i03` | Ведущий ноль удалён |
| `W01` | `w1` | Приведено к нижнему регистру |
| `INCL01` | `i01` | Расширенная форма типа сокращена |
| `i03_` | `i03_` | Завершающее подчёркивание НЕ удаляется (дополнительная запись) |

### Шаблоны идентификаторов устройств по умолчанию

Определены в [`config.py`](../../src/meta_finder/config.py):

- **device_type_pattern**: `r"incl|wg|[iw]"` - соответствует типу устройства без номера
- **device_model_pattern**: `r"[bp]?"` - опциональный суффикс модели
- **device_number_pattern**: `r"\d+"` - номер устройства
- **device_id_pattern**: `fr"(?:{device_type_pattern})(?:{device_model_pattern})?{device_number_pattern}"` - соответствует полным идентификаторам устройств
- **device_id_complex_pattern**: `r"\d*[@#_-]?(?P<type>{device_type_pattern})(?:ncl|nkl)?_?(?P<model>{device_model_pattern})0*(?P<number>{device_number_pattern})"` - для извлечения идентификаторов устройств с опциональными префиксами и разделителями
- **devices_in_text_output_files_pattern**: Гибкий шаблон для имён файлов text_output

## Приоритет обнаружения устройств

### Приоритет анализа имён файлов данных

1. **Приоритет интервала осреднения**: Файлы с меньшими интервалами осреднения имеют более высокий приоритет (2с > 600с > 7200с)
2. **Файлы без информации об осреднении**: Обрабатываются как имеющие настроенное значение осреднения по умолчанию (2.0001с)
3. **Специфичность**: Выделенные файлы (для конкретных устройств) > комбинированные файлы
4. **Число устройств**: Файлы с меньшим числом устройств > файлы с большим числом устройств
5. **Число несовпадающих устройств**: Файлы с меньшим числом несовпадающих устройств > файлы с большим числом

### Порядок приоритета источников

1. **Анализ имён файлов данных** (директория text_output или архивы)
2. **Поиск в сырой директории** (`_raw/` директория)
3. **Поддержка HDF5/MAT** (когда text_output и сырые файлы недоступны)

Для HDF5 файлов:
- `*.proc_noAvg.h5` — приоритет 2 (наивысший)
- `*.proc_Avg.h5` — приоритет 3
- `*.proc.h5` — приоритет 4
- `_raw/*.h5` — приоритет 5
- `_raw/*.mat` — приоритет 6 (наинизший)

## Выходные форматы

### `meta_TCM.tsv`

Табуляция-разделённая таблица с консолидированными метаданными. См. [Руководство по вводу/выводу](../user_guide/input_output_Ru.md) для описаний столбцов.

### `files_TCM.tsv`

Текстовый список путей, сгруппированных по экспедиции:

```
path/to/device/dir/cruise1
path/to/data/file1.tsv
path/to/data/file2.tsv

path/to/device/dir/cruise2
path/to/data/file3.tsv
```

## Формат файлов метаданных

Система читает файлы метаданных в порядке приоритета:
1. `info_devices@meta_finder.yaml`
2. `info_devices.yaml`
3. `info_devices.json` (устаревший)

### YAML формат

```yaml
# Instrument_ID: [Point, Sea_depth, H_above_bot, Symbol, Lat, Lon, Time_st, Time_en, Burst_dt, Bursts_t, Comment]
i03: ["P1", 15, 0.5, "⯯", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
w01: ["P1", 15, 5, "", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
```

### Порядок элементов массива

| Индекс | Поле | Описание | Обязательный |
|--------|------|----------|--------------|
| 0 | `point` | Название/номер станции | Да |
| 1 | `sea_depth` | Глубина моря (м) | Да |
| 2 | `height_above_bottom` | Высота прибора над дном (м) | Да |
| 3 | `modification_symbol` | Символ модификации | Да |
| 4 | `lat` | Широта (градусы) | Нет |
| 5 | `lon` | Долгота (градусы) | Нет |
| 6 | `time_st` | Время начала данных | Нет |
| 7 | `time_en` | Время конца данных | Нет |
| 8 | `burst_dt` | Интервал активности (с) | Нет |
| 9 | `bursts_t` | Период работы (с) | Нет |
| 10 | `comment` | Комментарий | Нет |
| 11 | `coef_date` | Дата калибровки (из HDF5) | Нет |
| 12 | `time_raw_st` | Начало raw-данных | Нет |
| 13 | `time_raw_en` | Конец raw-данных | Нет |

- **Минимальная длина массива:** 4 элемента (первые 4 обязательных поля).
- **Отсутствующие элементы** заполняются значениями по умолчанию: `?` для большинства полей, `""` для `burst_dt`, `bursts_t`, `coef_date`, `time_raw_st`, `time_raw_en`.
- **Значения `null`/`~`** в YAML обрабатываются как отсутствующие.
- **Идентификаторы приборов с пробелом в начале** (например, `" i10"`) игнорируются — это соглашение о приборе, по которому данные ещё не собраны.

### Множественные интервалы

Для устройств с несколькими интервалами постановки используйте вложенную структуру:

```yaml
i03:
  0: ["P1", 15, 0.5, ?, 54.7, 19.8, "2023-05-08 12:00:00", "2023-05-15 08:00:00", -, -, ""]
  1: ["P2", 20, 1.0, ?, 54.9, 20.1, "2023-06-01 10:00:00", "2023-06-10 14:00:00", 120, 600, ""]
```
