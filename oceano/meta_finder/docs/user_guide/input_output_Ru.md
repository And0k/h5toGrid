# Руководство по вводу/выводу

Это руководство описывает форматы данных, принимаемые и производимые meta_finder.
Для авторитетных контрактов форматов см. [Спецификация форматов ввода/вывода](../reference/io_formats_Ru.md).

## Входные данные

Программа обнаруживает и обрабатывает данные из трёх основных источников:

### Текстовые файлы данных (text_output)

Табуляция-разделённые текстовые файлы, содержащие обработанные данные приборов:

**Файлы данных инклинометра (tilt current meter) содержат следующие заголовочные столбцы данных (с tab-разделителем):**
- Time – Калининградское время, `yyyy-mm-dd HH:MM:SS.ffffff`, (в старых версиях столбец также может называться `index`)
- Vabs – абсолютное значение скорости течения, м/с
- Vdir – направление скорости течения, ° в географической системе координат
- v – северная компонента скорости течения, м/с
- u – восточная компонента скорости течения, м/с
- Inclination – угол наклона инклинометра, °
- Temp – температура процессора инклинометра, °C

**Файлы данных волнографов содержат следующие заголовочные столбцы данных (с tab-разделителем):**
- Time – Калининградское время, `yyyy-mm-dd HH:MM:SS.ffffff`
- Pressure – давление, dBar

**Файлы данных, объединяющие данные от нескольких устройств**, обычно содержат меньший набор столбцов для каждого устройства; столбцы данных имеют суффикс имени устройства. Пример:

```
index  v_i03  u_i03  Temp_i03  v_i04  u_i04  Temp_i04
```

### HDF5 и MAT файлы

MAT файлы (.mat) в директориях `_raw` обрабатываются так же, как HDF5 файлы с сырым приоритетом.

**Не .proc.h5 файлы содержат группы:**
- `device_id` (может быть нормализованным или нет, например, `i07`, `w01`, `inclinometer07`, `@i07`)
- `table` (таблица данных) со столбцами по именам параметров
- `coef` (только в файлах сырой директории или с суффиксом `.raw.h5`) - группа с коэффициентами и их метаданными

**.proc_noAvg.h5:**
```
/
├── i63/  # device_id_proc (нормализованное имя устройства)
│   ├── table (столбцы: ['index', 'v', 'u', 'inclination', 'Battery', 'Temp'])
│   └── logFiles/
│       └── table (столбцы: ['index', 'fileName', 'fileChangeTime', 'DateEnd', 'DateProc'])
```

**.raw.h5:**
```
/
├── incl63/  # device_id_raw (ненормализованное имя устройства)
│   ├── table (столбцы: ['index', 'Ax', 'Ay', 'Az', 'Mx', 'My', 'Mz', 'Battery', 'Temp'])
│   ├── coef/
│   └── logFiles/
│       └── table (столбцы: ['index', 'fileName', 'fileChangeTime', 'DateEnd', 'DateProc'])
```

**.proc.h5 файлы содержат группы:**
- averaging_bin (содержит информацию об осреднении в имени, например, `bin600s`)
- `table` (таблица данных) со столбцами параметров, содержащими суффиксы device_id

**.proc_Avg.h5 файлы содержат группы:**
- device_id с осреднением bin (например, `i04bin2s`, `i03bin600s`) - идентификаторы устройств в именах групп, а не в именах столбцов
- `table` (таблица данных) со столбцами имён параметров БЕЗ суффиксов device_id (столбцы типа "Vabs", "v", "u" и т.д.)

Структура примера:
```
/
├── i04bin2s/  # device_id с averaging bin
│   └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
├── i05bin2s/  # другое устройство с тем же осреднением
│   └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
└── i03bin600s/  # устройство с другим осреднением
    └── table (столбцы: ['index', 'Vabs', 'Vdir', 'v', 'u', 'Inclination', 'Temp'])
```

## Структура директорий экспедиций

Программа ожидает следующую стандартную структуру директорий:

```
B:/WorkData/BalticSea/
└── YYMMDD_{название_экспедиции}/
    ├── *inclinometer* или *wavegauge*/
    │   ├── info_devices@meta_finder.yaml  ← приоритет 1 (генерируется автоматически, если находятся данные отсутствующие в info_devices.yaml)
    │   ├── info_devices.yaml              ← приоритет 2
    │   ├── info_devices.json              ← приоритет 3 (устаревший)
    │   ├── text_output/
    │   │   └── *.tsv, *.txt, *.csv        ← обработанные текстовые данные
    │   ├── text_output.zip                ← альтернатива: архив текстовых данных
    │   ├── text_output.7z
    │   ├── *.proc_noAvg.h5               ← обработанные HDF5 без осреднения
    │   ├── *.proc.h5                     ← обработанные HDF5 с осреднением
    │   ├── *.proc_Avg.h5                 ← обработанные HDF5 (группы по приборам)
    │   └── _raw/
    │       ├── *.h5, *.mat               ← «сырые» данные
    │       └── *.txt, *.tsv, *.csv       ← «сырые» текстовые данные
    └── *navigation* или *map*/
        └── *.gpx                         ← навигационные файлы
```

Также поддерживаются комбинированные структуры:
- `YYMMDD{название}/{device_type}/info_devices.yaml`
- `YYMMDD{название}/info_devices.yaml` (метаданные в корне)
- `YYMMDD{название}/inclinometers/{YYMMDD}*/info_devices.yaml` (вложенные датированные подкаталоги)

## Выходные файлы

Программа создаёт два выходных файла в директории `meta`:

| Файл | Описание |
|------|----------|
| `{yymmdd_HHMM}_files_TCM.tsv` | Список всех обработанных файлов, сгруппированных по экспедиции |
| `{yymmdd_HHMM}_meta_TCM.tsv` | Табуляция-разделённая таблица с консолидированными метаданными для всех устройств |

### Столбцы таблицы метаданных

| Столбец | Описание |
|---------|----------|
| `setup_name` | Имя набора данных — уникальный идентификатор, комбинирующий название экспедиции с опциональным датным префиксом и суффиксом устройства |
| `device_id` | Нормализованный идентификатор устройства (например, i7, w1) |
| `point` | Название/номер станции |
| `sea_depth` | Глубина моря в точке постановки (м) |
| `height_above_bottom` | Высота прибора над дном (м) |
| `lat` | Широта точки постановки или ? |
| `lon` | Долгота точки постановки или ? |
| `time_st` | Дата начала обработанных данных (с точностью до секунд) |
| `time_en` | Дата конца обработанных данных (с точностью до секунд) |
| `burst_dt` | Интервал активности прибора в секундах (периодический режим) |
| `bursts_t` | Период работы прибора в секундах (периодический режим) |
| `data_file_path` | Путь к одному обработанному текстовому файлу на диске |
| `quality` | Индикатор качества: `+-` для амплитуды+направления, `+` для обработанных, `-` для отсутствующих, `?` для сырых |
| `comment` | Комментарии включая информацию о комбинированных устройствах и GPX путях |
| `modification_symbol` | Символ модификации/конструкции прибора |
| `coef_date` | Дата калибровочных коэффициентов (из HDF5) |
| `time_raw_st` | Начало сырых данных (из HDF5/MAT в `_raw/`) |
| `time_raw_en` | Конец сырых данных (из HDF5/MAT в `_raw/`) |

### Правила формата вывода

- Поля, не найденные программой, заполняются знаком "?"
- Значения `burst_dt` и `bursts_t`, равные "-", означают, что прибор работал нормально без периодического выключения
- Координаты записываются в градусах; если не найдены, для `lat` и `lon` записывается "?", а пути ко всем найденным GPX файлам записываются в поле `comment` с префиксом "GPX:"
- Для комбинированных столбцов данных (например, `Vabs_i05_14`) в поле `comment` содержится "{device1}+{device2} output"

## Форматы времени

Поля времени (`time_st`, `time_en`, `coef_date` и др.) принимают форматы ISO:

| Формат | Пример |
|--------|--------|
| `YYYY-MM-DD HH:MM:SS` | `2019-12-10 14:22:00` |
| `YYYY-MM-DDTHH:MM:SS` | `2019-12-10T14:22:00` |
| `YYYY-MM-DDTHH:MM` | `2019-12-10T14:22` |
| `YYYY-MM-DD HH:MM` | `2019-12-26 12:40` |
| `YYYY-MM-DDTHH:MM:SS.ffffff` | `2019-12-10T14:22:00.123456` |

Все форматы нормализуются к `YYYY-MM-DD HH:MM:SS` при чтении.

## Символы модификации

| Символ | Значение |
|--------|----------|
| `⯯` | Отрицательная плавучесть (самый широкий диапазон) |
| `⯭` | Положительная плавучесть, широкий диапазон (с большим поплавком) |
| `⭡` | Положительная плавучесть, узкий диапазон измеряемой скорости течения |
| `⤉` | Положительная плавучесть, со штангой |
| `↑` | Положительная плавучесть, символ не используется |
