# Руководство по CLI

Задача-ориентированное руководство по интерфейсу командной строки `meta_finder`.
Для справочника по конфигурации см. [Справочник по конфигурации](../reference/config_reference_Ru.md).
Для деталей реализации (архитектура модулей, поток функций) см. [CLI Internals](../project_developer_guide/CLI_Ru.md).

## Базовый вызов

```bash
# Обработать все директории экспедиций
pixi run collect

# Обработать конкретную директорию экспедиции
pixi run collect --cruise-dir "B:/Cruises/BalticSea/250415_ABP60"

# Создать/обновить info_devices@meta_finder.yaml файлы
pixi run collect --create-info-files --no-from-data

# Извлечь временные метаданные из файлов данных
pixi run collect --create-info-files
```

## Первый запуск на новых данных

При обработке директорий экспедиций в первый раз (или когда файлы `info_devices@meta_finder.yaml` не существуют), программа обнаруживает устройства из файлов данных и создаёт YAML-файлы с значениями-заполнителями. Однако **извлечение временных данных происходит только для устройств, уже перечисленных в существующих YAML-файлах метаданных**, чтобы просмотреть и отредактировать списки устройств перед извлечением времени.

Это означает, что обычно нужно запускать программу **дважды**:

1. **Первый запуск** (с `--create-info-files --no-from-data`):
   - Обнаруживает все устройства из файлов данных (text_output, _raw, HDF5)
   - Создаёт `info_devices@meta_finder.yaml` файлы со всеми обнаруженными устройствами
   - Устройства имеют значения-заполнители ("?") для временных полей
   - Программа покажет предупреждение: "NEW DEVICES FOUND - REQUIRES SECOND RUN"

2. **Второй запуск** (с `--create-info-files`):
   - Читает существующие `info_devices@meta_finder.yaml` файлы
   - Извлекает временные данные из файлов данных для устройств, перечисленных в YAML
   - Обновляет устройства фактическими временными диапазонами (time_st, time_en, burst_dt, bursts_t)
   - Сохраняет все остальные метаданные из первого запуска

## Переключатели команд

| Переключатель | Описание |
|--------------|----------|
| `--interactive`, `-i` | Запросить каждый параметр конфигурации по порядку; введите `*` для использования значений по умолчанию для всех остальных настроек |
| `--create-info-files` | Создать или обновить `info_devices@meta_finder.yaml` файлы из существующих структур данных |
| `--no-from-data` | Пропустить извлечение метаданных из файлов данных; использовать только существующие файлы метаданных |
| `--cruise-dir` | Указать одну директорию экспедиции для обработки, переопределяя `--search-dirs` |
| `--config` | Загрузить конфигурацию из JSON-файла конфигурации |

## Поведение при повторном запуске

Pipeline обрабатывает идемпотентность автоматически:

| Вывод | Поведение при повторном запуске |
|-------|--------------------------------|
| `info_devices@meta_finder.yaml` | **Обновляется** — только устройства со всеми пустыми значениями получают новую информацию |
| `meta_TCM.tsv` | **Перезаписывается** — регенерируется из текущего состояния |
| `files_TCM.tsv` | **Перезаписывается** — регенерируется из текущего состояния |

Когда `overwrite_bad_devs_in_info_files=True` (по умолчанию), только устройства со всеми пустыми значениями ("?", "-", или "") обновляются новой информацией, сохраняя существующие не-заполнительные значения.
