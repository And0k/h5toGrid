# Metadata table description

The metadata table is produced by **meta_finder** as `*_meta_TCM.tsv` during cruise directory scanning, followed by minor manual editing. It contains consolidated metadata for all discovered devices (inclinometers and wave gauges) and their data.

## 1.1. Header structure

The header row is generated by [`write_metadata_table()`](../src/meta_finder/file_writer.py#L93) and contains the following columns (in order):

| #   | Column name                 | Description                                                                  | Source besides info file |
| --- | --------------------------- | ------------------------------------------------------------------------- | ------------------------ |
| 1   | `setup_name`                | Dataset name (cruise or device name combined with date)                    | device directory path    |
| 2   | `device_id`                 | Instrument identifier                                                      | data file path / HDF5 group name |
| 3   | `point`                     | Station name/number                                                        | —                        |
| 4   | `sea_depth`                 | Sea depth at station (m)                                                   | —                        |
| 5   | `height_above_bottom`       | Height of instrument above bottom (m)                                      | —                        |
| 6   | `lat`                       | Latitude (degrees)                                                         | —                        |
| 7   | `lon`                       | Longitude (degrees)                                                        | —                        |
| 8   | `time_st`                   | Start time of processed data (to the second)                               | text data file (first row) |
| 9   | `time_en`                   | End time of processed data (to the second)                                 | text data file (last row) |
| 10  | `burst_dt`                  | Instrument active interval in seconds (periodic mode)                      | text data file (gap analysis) |
| 11  | `bursts_t`                  | Instrument operation period in seconds (periodic mode)                     | text data file (gap analysis) |
| 12  | `data_file_path/data_paths` | Path(s) to data file(s) on disk                                            |                          |
| 13  | `quality`                   | Data source quality indicator                                              | based on found data types |
| 14  | `comment`                   | Comments                                                                    | combined files / GPX     |
| 15  | `modification_symbol`       | Instrument modification/construction symbol                                |                          |
| 16  | `coef_date`                 | Calibration coefficient date (from HDF5)                                   | `_raw/*.h5`              |
| 17  | `time_raw_st`               | Start of raw data (from HDF5/MAT in `_raw/`)                               | `_raw/*.h5`              |
| 18  | `time_raw_en`               | End of raw data (from HDF5/MAT in `_raw/`)                                 | `_raw/*.h5`              |

## 1.2. Column details and data origins

### `setup_name` — Dataset name (cruise + date + device)

- **Source:** automatically generated from cruise directory name by [`add_dataset_name()`](../src/meta_finder/parse_cruise_dir_name.py#L159) using the following algorithm:
  1. Date and device-related suffixes are removed from the cruise directory name (e.g. `YYMMDD_name`). Device keywords (`inclinometer`, `wavegauge`, etc.) and instrument IDs after `@`, `#` are stripped.
  2. If the resulting name contains no digits, `/` separator is used between date and name: `1305/Sambian`.
  3. If the name contains digits (cruise number), `_` separator is used: `171017_ANS36`, `230616Kulikovo`.
  4. When names of different cruises coincide, additional date components (YYMM or YYMMDD) are appended to ensure uniqueness.

### `device_id` — Instrument identifier

- **Source:** extracted from multiple sources in priority order:
  1. Data file name in `text_output/` (function [`parse_filename_for_metadata()`](../src/meta_finder/parse_data_file_name.py)).
  2. Data file contents (column names) when generic types (`*`, `i`, `w`, `p`) are present.
  3. Subdirectory name inside `text_output/` (function `_extract_device_id_from_subdirectory_name()`).
  4. Files in `_raw/` directory.
  5. HDF5 file groups.
- **Format:** normalized identifier: type + model + number. Leading zeros and underscores are removed.
  - `i3` — inclinometer No. 3
  - `w1` — wave gauge No. 1 (may contain inclinometer columns, but is not intended for use as inclinometer)
  - `ib27` — inclinometer model `b` No. 27
  - `ip6` — inclinometer model `p` (with pressure sensor) No. 6
- **Normalization:** performed by [`normalize_device_id()`](../src/meta_finder/parse_data_file_name.py); `i_03` → `i3`, `i_b27` → `ib27`, `W01` → `w1`.

### `point` — Station name/number

- **Source:** field `point` (index 0) from the info file ([`info_devices*.yaml` or `*.json`](../src/meta_finder/config.py#L17) in the device directory). Default: `?`.

### `sea_depth` — Sea depth

- **Source:** field `sea_depth` (index 1) from the info file. Default: `?`. Units: meters.

### `height_above_bottom` — Height above bottom

- **Source:** field `height_above_bottom` (index 2) from the info file. Default: `?`. Units: meters.

### `modification_symbol` — Modification/construction symbol

- **Source:** field `modification_symbol` (index 3) from the info file. Default: `?`.
- **Examples:**
  - `⯯` — negative buoyancy (widest range)
  - `⯭` — positive buoyancy, wide range (large float)
  - `⭡` — positive buoyancy, narrow current speed measurement range
  - `⤉` — positive buoyancy, with rod

### `lat` — Latitude

- **Source:** field `lat` (index 4) from the info file. Default: `?`. Format: decimal degrees.

### `lon` — Longitude

- **Source:** field `lon` (index 5) from the info file. Default: `?`. Format: decimal degrees.

### `time_st` — Start time of processed data

- **Source (in priority order):**
  1. From the info file (field `time_st`, index 6). If not extracted from data, default: `?`.
  2. From text data file (function [`extract_time_info_from_text_file()`](../src/meta_finder/data_proc_funcs.py)) — reading first and last data rows.
  3. From HDF5 file (function [`extract_time_range_from_hdf5_table()`](../src/meta_finder/hdf5_processor.py)) when `extract_hdf5_times` option is enabled.
- **Format:** `YYYY-MM-DD HH:MM:SS`.

### `time_en` — End time of processed data

- **Source:** similar to `time_st` (index 7 in the info file). If not extracted from data, default: `?`.
- **Format:** `YYYY-MM-DD HH:MM:SS`.

### `burst_dt` — Instrument active interval

- **Source:**
  1. Field `burst_dt` (index 8) from the info file. If not extracted from data, default: `-` — means the instrument operated continuously (without periodic shutdown), or burst-mode data is absent.
  2. Computed when extracting time data from text files: if an averaging interval is specified, time gaps are analyzed to determine burst-mode parameters.
- **Units:** seconds.

### `bursts_t` — Instrument operation period

- **Source:**
  1. Field `bursts_t` (index 9) from the info file. If not extracted from data, default: `-` — similar to `burst_dt`.
- **Units:** seconds.

### `data_file_path` / `data_paths` — Data file path(s)

- **Source:** generated from discovered data files for each instrument. If no data files are found, default: `?`.
- **Default mode** (`data_file_path`): one path is written — to the highest-priority data file (see "Data source priorities" section).
- **Extended mode** (`data_paths`, with `--write-all-collected-paths` flag): all discovered data file paths are written, comma-separated.

### `quality` — Data source quality indicator

- **Source:** user assessment of data (manual). By default computed from the data file path in [`write_metadata_table()`](../src/meta_finder/file_writer.py#L244) using these values:
  - `+` — data from processed file (`text_output`, `.proc.h5`, etc.; path **does not contain** `_raw`).
  - `-` — data file not found (path = `?`).
  - `?` — data from raw source (path contains `_raw`).
- If amplitude and direction can be assessed differently, amplitude assessment comes first, then direction (e.g. "+-"). If the instrument measured both pressure and velocity, pressure is not assessed.

### `comment` — Comment

- **Source (combined with `;`, default: empty string):**
  - Field `comment` (index 10) from the info file — user comment.
  - If **combined files** were used as data source (where a data column is composed of sequential data from multiple instruments, header like `Vabs_i05_14`), the program may add a comment like `{device1}+{device2} output`.

### `coef_date` — Calibration coefficient date

- **Source:** extracted from HDF5 files in `_raw/` directory (group `coef`) when `extract_hdf5_coef_dates` is enabled or `coef_date` is in `raw_hdf5_cols`. Default: `?`.
- **Format:** `YYYY-MM-DD HH:MM:SS`.

### `time_raw_st` — Raw data start

- **Source:** extracted from files in `_raw/` directory. Default: `?`.
- **Format:** `YYYY-MM-DD HH:MM:SS`.

### `time_raw_en` — Raw data end

- **Source:** similar to `time_raw_st`. Default: `?`.
- **Format:** `YYYY-MM-DD HH:MM:SS`.

## 1.3. Data source priorities

The priority system determines which file is used to extract time data (`time_st`, `time_en`, `burst_dt`, `bursts_t`) for each instrument. Sorting is performed by [`sort_data_paths()`](../src/meta_finder/data_processor.py#L87).

**Three-level priority scheme:**

| Priority | Level | Description |
|----------|-------|-------------|
| **1st** | Processed vs raw | Processed data (`text_output`, `.proc.h5`) takes priority over raw (`_raw/`, raw `.h5`/`.mat`). |
| **2nd** | Averaging interval | Optimal value is 2 s. Priority decreases as the interval moves away from 2 s in either direction (up to 300 s or down). For HDF5 files, averaging ≤ 2 s is treated as 2 s. Files without specified averaging get default 2.0001 s (slightly lower priority than 2 s). |
| **3rd** | Source type | Among files of the same level: directories > archives (.zip/.7z) > `proc_noAvg.h5` > `proc_Avg.h5` > `proc.h5` > raw `.h5` > `.mat`. |

**Additional tie-breaking criteria:**

| Priority | Criterion | Description |
|----------|-----------|-------------|
| **4th** | Specificity | Files for specific instruments take priority over combined files. |
| **5th** | Instrument count | Files with fewer instruments in the name take priority. |
| **6th** | Non-matching instruments | Files with fewer instruments not in the target set take priority. |

## 1.4. Conventions and placeholder values

**Data preservation policy:** when merging metadata from info files, data from later files takes priority (values (`?`, `""`, `None`, `-`) are not considered, see [`_update_time_fields()`](../src/meta_finder/collect.py#L217)).

## 1.5. Multiple intervals (multi-interval devices)

If an instrument has multiple deployment intervals (e.g., retrieved and redeployed), a nested structure is used in the info file:

```yaml
i03:
  0: [P1, 15, 0.5, ?, 54.7, 19.8, "2023-05-08 12:00:00", "2023-05-15 08:00:00", -, -, ""]
  1: [P2, 20, 1.0, ?, 54.9, 20.1, "2023-06-01 10:00:00", "2023-06-10 14:00:00", 120, 600, ""]
```

In this case, a **separate row is created for each interval** in the TSV file. The interval key (e.g. `0`, `1`) corresponds to the deployment name; by default, it is the sequential number starting from 0.

## 1.6. Row sorting

Rows in the table are sorted by dataset date (from the device directory or cruise directory name, function [`parse_dated_dir()`](../src/meta_finder/parse_cruise_dir_name.py#L25)) in ascending order. Within a single cruise, the order is determined by the device order in the info file.

## 2. Data directory structure

The program expects the following standard directory structure:

```
B:/WorkData/BalticSea/
└── YYMMDD_{cruise_name}/
    ├── *inclinometer* or *wavegauge*/
    │   ├── info_devices@meta_finder.yaml  ← priority 1 (auto-generated when data found missing from info_devices.yaml)
    │   ├── info_devices.yaml              ← priority 2
    │   ├── info_devices.json              ← priority 3 (deprecated)
    │   ├── text_output/
    │   │   └── *.tsv, *.txt, *.csv        ← processed text data
    │   ├── text_output.zip                ← alternative: archived text data
    │   ├── text_output.7z
    │   ├── *.proc_noAvg.h5               ← processed HDF5 without averaging
    │   ├── *.proc.h5                     ← processed HDF5 with averaging
    │   ├── *.proc_Avg.h5                 ← processed HDF5 (groups by instrument)
    │   └── _raw/
    │       ├── *.h5, *.mat               ← raw data
    │       └── *.txt, *.tsv, *.csv       ← raw text data
    └── *navigation* or *map*/
        └── *.gpx                         ← navigation files
```

Combined structures are also supported:
- `YYMMDD{name}/{device_type}/info_devices.yaml`
- `YYMMDD{name}/info_devices.yaml` (metadata in root)
- `YYMMDD{name}/inclinometers/{YYMMDD}*/info_devices.yaml` (nested dated subdirectories)

Instead of `YYMMDD`, `YYMM` or `YYMM..YYMM` may be used (for data dates, only the leading digits are used; digits and separators are stripped from `{name}`).

## 3. Informational files — metadata sources

Data in `meta_TCM.tsv` columns comes from informational files, searched in the following priority order (function [`read_metadata_files()`](../src/meta_finder/metadata_extractor.py#L55)):

| Priority | File name | Format | Description |
|----------|-----------|--------|-------------|
| 1 (highest) | `info_devices@meta_finder.yaml` | YAML | File created/updated by meta_finder program |
| 2 | `info_devices.yaml` | YAML | User metadata file |
| 3 (lowest) | `info_devices.json` | JSON | Deprecated format |

The file contains a `device_id: [array]` structure (or nested structure for multiple intervals):

```yaml
# Instrument_ID: [Point, Sea_depth, H_above_bot, Symbol, Lat, Lon, Time_st, Time_en, Burst_dt, Bursts_t, Comment]
i03: ["P1", 15, 0.5, "⯯", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
w01: ["P1", 15, 5, "", 54.7123, 19.8456, "2023-05-08 12:00:00", "2023-06-15 08:30:00", -, -, ""]
```

**Array element order** (defined by [`info_devices_field_names_extended`](../src/meta_finder/io_info_files.py#L37)):

| Index | Field | Description | Required |
|-------|-------|-------------|----------|
| 0 | `point` | Station name/number | Yes |
| 1 | `sea_depth` | Sea depth (m) | Yes |
| 2 | `height_above_bottom` | Height above bottom (m) | Yes |
| 3 | `modification_symbol` | Modification symbol | Yes |
| 4 | `lat` | Latitude (degrees) | No |
| 5 | `lon` | Longitude (degrees) | No |
| 6 | `time_st` | Data start time | No |
| 7 | `time_en` | Data end time | No |
| 8 | `burst_dt` | Active interval (s) | No |
| 9 | `bursts_t` | Operation period (s) | No |
| 10 | `comment` | Comment | No |
| 11 | `coef_date` | Calibration date (from HDF5) | No |
| 12 | `time_raw_st` | Raw data start | No |
| 13 | `time_raw_en` | Raw data end | No |

- **Minimum array length:** 4 elements (first 4 required fields).
- **Missing elements** filled with defaults: `?` for most fields, `""` for `burst_dt`, `bursts_t`, `coef_date`, `time_raw_st`, `time_raw_en`.
- **`null`/`~` values** in YAML treated as missing.
- **Leading space in device IDs** (e.g. `" i10"`) ignored — convention for instruments not yet collected.

### 3.2. Time formats

Time fields (`time_st`, `time_en`, `coef_date`, etc.) accept ISO formats:

| Format | Example |
|--------|---------|
| `YYYY-MM-DD HH:MM:SS` | `2019-12-10 14:22:00` |
| `YYYY-MM-DDTHH:MM:SS` | `2019-12-10T14:22:00` |
| `YYYY-MM-DDTHH:MM` | `2019-12-10T14:22` |
| `YYYY-MM-DD HH:MM` | `2019-12-26 12:40` |
| `YYYY-MM-DDTHH:MM:SS.ffffff` | `2019-12-10T14:22:00.123456` |

All formats are normalized to `YYYY-MM-DD HH:MM:SS` on read (function [`info_meta_list_to_dict()`](../src/meta_finder/metadata_extractor.py#L16)).

## 5. Data file names and instrument ID extraction

### 5.1. Supported file name patterns

| Pattern | Example | Extracted data |
|---------|---------|----------------|
| `{datetime}bin{interval}s[@_#]{devices}.tsv` | `191108_1200bin600s@i03.tsv` | devices: i03, bin: 600s |
| `{date}#{devices}-bin{interval}s.{ext}` | `191210#07,23,30,32-bin300s.zip` | devices: i07,i23,i30,i32, bin: 300s |
| `{date}#{devices}.{ext}` | `191210#i03.tsv` | devices: i03 |
| `{date}_{time}_{device}.{ext}` | `200113_0000_i13.csv` | device: i13 |
| `{date}_{time}@{device}.{ext}` | `200113_00@i13.csv` | device: i13 |

### 5.2. Complex identifier patterns

- **Semicolon** separates instrument groups: `i3,4,15;ib27-30,ip6.tsv`
- **Ranges** expand: `27-30` → `["27", "28", "29", "30"]`
- **Parentheses:** `i(38,37,59,60,58).tsv` → `i38,i37,i59,i60,i58`

### 5.3. Identifier normalization

| Original | Normalized | Note |
|----------|------------|------|
| `i_03` | `i03` | Underscore after type removed |
| `i_b27` | `ib27` | Underscore between type and model removed |
| `i_p06` | `ip06` | Similar |
| `W1` | `w1` | Lowercased |
| `INCL01` | `i01` | Expanded type form shortened |
| `i03_` | `i03_` | Trailing underscore **not** removed (additional entry) |

## 6.1. Info file format

File `{YYMMDD_HHMM}_files_TCM.tsv` — file list

### Format

The file is a text list of paths, grouped by cruise. Generated by [`write_files_list()`](../src/meta_finder/file_writer.py#L14).

**Structure:**

```
path/to/device/dir/cruise1
path/to/data/file1.tsv
path/to/data/file2.tsv
...

path/to/device/dir/cruise2
path/to/data/file3.tsv
...
```

### Content description

For each cruise, entries are formed as follows:

1. **First row of the group** — path to the device directory in POSIX format.
2. **Subsequent rows** — paths to data files for each instrument in this directory.

**Entry order:**
- Cruises sorted by date (from `cruise_date_map`), then by name.
- Device directories within a cruise sorted by path.
- Instruments within a directory sorted by `device_id`.
- Data files for each instrument sorted by priority (as described in section 1.3).

**Files per instrument:**
- Default: **one** data file (highest priority) for each instrument.
- With `--write-all-collected-paths` flag: **all** discovered data files for each instrument.

**Cruise groups are separated by an empty line.**

### Included file types

The list includes paths from the following sources:

| Source | Extensions | Description |
|--------|------------|-------------|
| `text_output/` (directories and archives) | `.tsv`, `.txt`, `.csv` | Processed text data |
| `_raw/` | `.txt`, `.tsv`, `.csv`, `.h5`, `.hdf5`, `.mat` | Raw instrument data |
| HDF5 (device_dir root) | `.h5` | Processed HDF5: `.proc_noAvg.h5`, `.proc.h5` |
| Subdirectories with `h5` in name | `.h5` | Additional HDF5 files |
