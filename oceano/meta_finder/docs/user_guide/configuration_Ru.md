# Руководство по конфигурации

Программа использует систему конфигурации на базе датаклассов с аргументами командной строки. Конфигурация определена в датаклассе `Config` в [`config.py`](../../src/meta_finder/config.py).

## Ключевые параметры конфигурации

- `search_dirs`: Список директорий для поиска данных экспедиций (жёстко заданный путь по умолчанию обычно не то, что вам нужно: укажите явно или переопределите параметром `cruise-dir`)
- `cruise_dir`: Указывает одну директорию экспедиции для обработки, переопределяя `--search-dirs` (по умолчанию: None). Полезно для отладки конкретных директорий экспедиций.
- `create_info_files`: Создавать или обновлять файлы `info_devices@meta_finder.yaml` (по умолчанию: False)
- `from_data`: Извлекать метаданные из файлов данных. Когда True, извлекает метаданные (временные диапазоны, информацию об устройствах и т.д.) из файлов данных и объединяет с существующими метаданными. Когда False, использует только метаданные из существующих файлов метаданных (по умолчанию: True)
- `extract_hdf5_times`: Извлекать временные метаданные из HDF5 файлов в порядке приоритета (когда файлы text_output недоступны): `*.proc_noAvg.h5`, `*.proc.h5`, и `_raw/*.h5` (по умолчанию: True)
- `extract_hdf5_coef_dates`: Извлекать даты коэффициентов из HDF5 файлов (по умолчанию: False)
- `max_burst_time_detection`: Максимальное время в секундах для анализа burst-режима (по умолчанию: 10800 = 3 часа). Код читает строки 1 и 20 для вычисления временного интервала, затем вычисляет, сколько строк необходимо для покрытия этого временного промежутка.
- `default_text_file_averaging`: Значение осреднения по умолчанию для текстовых файлов, которые не указывают осреднение (по умолчанию: 2.0001 секунды, чтобы обрабатывать их как файлы более низкого приоритета для извлечения времени, чем файлы с обычно достаточным осреднением 2с)
- `device_dir_pattern`: Шаблон regex для идентификации стандартных директорий устройств. Соответствует ключевым словам устройств (`inclinometer`, `incl`, `tcm`, `wavegauge`, `wave_gauge`, `pres`, `@i[0-9]`) или типам устройств (`i`, `w`, `incl`, `wg`) после разделителей (`_`, `@`, `#`, цифры, `-`). Типы устройств требуют якоря запятой, точки с запятой или конца строки.

## Другие параметры конфигурации

- `output_dir`: Выходная директория для генерируемых файлов (по умолчанию: None, что использует директорию "meta" относительно текущей рабочей директории)
- `raw_hdf5_cols`: Множество столбцов для запуска извлечения соответствующей информации из RAW HDF5/MAT файлов (из `_raw/*.h5` и `_raw/*.mat`). Опции включают "coef_date" и "raw_date_range" (по умолчанию: `{"coef_date", "raw_date_range"}`)
- `logging_level`: Глобальная настройка уровня логирования. Может быть указана как строка (DEBUG, INFO, WARNING, ERROR, CRITICAL) или числовое значение (по умолчанию: INFO, что равно 20)
- `output_format`: Выходные форматы для генерации (по умолчанию: `["tsv"]`)
- `overwrite_bad_devs_in_info_files`: Управляет выборочным обновлением отдельных записей устройств в info-файлах: только устройства со всеми пустыми значениями ("?", "-", или "") обновляются новой информацией, сохраняя существующие не-заполнительные значения; сохраняет порядок устройств в `info_devices@meta_finder.yaml` во время обновлений (по умолчанию: True)
- `cache_files_number`: Конфигурация кэширования для чтения файлов для минимизации избыточного доступа к файлам (по умолчанию: 2000)
- `temp_dir`: Настройки временной директории. Если не указано, по умолчанию используется `src/meta_finder/temp` (по умолчанию: None)

Все параметры конфигурации могут быть установлены через аргументы командной строки, с опциональной поддержкой загрузки из JSON-файла конфигурации с использованием опции `--config`.

## Требование двух запусков

При обработке директорий экспедиций в первый раз (или когда файлы `info_devices@meta_finder.yaml` не существуют), программа обнаруживает устройства из файлов данных и создаёт YAML-файлы с значениями-заполнителями. Однако **извлечение временных данных происходит только для устройств, уже перечисленных в существующих YAML-файлах метаданных**, чтобы просмотреть и отредактировать списки устройств перед извлечением времени.

Это означает, что обычно нужно запускать программу **дважды**:

1. **Первый запуск** (с `--create-info-files --no-from-data`):
   - Обнаруживает все устройства из файлов данных (text_output, _raw, HDF5)
   - Создаёт `info_devices@meta_finder.yaml` файлы со всеми обнаруженными устройствами
   - Устройства имеют значения-заполнители ("?") для временных полей

2. **Второй запуск** (с `--create-info-files`):
   - Читает существующие `info_devices@meta_finder.yaml` файлы
   - Извлекает временные данные из файлов данных для устройств, перечисленных в YAML
   - Обновляет устройства фактическими временными диапазонами (time_st, time_en, burst_dt, bursts_t)
   - Сохраняет все остальные метаданные из первого запуска

## Среды выполнения

Проект настроен с использованием pixi в режиме редактируемой разработки (см. [`pyproject.toml`](../../pyproject.toml)), поэтому модули должны импортироваться напрямую без необходимости изменения sys.path.

## Запуск тестов

Для запуска тестов используйте среду pixi "test":

```bash
# Запустить все тесты
pixi run -e test python -m pytest tests/

# Запустить конкретный тестовый файл
pixi run -e test python -m pytest tests/test_combined_file_processing.py

# Запустить тесты с подробным выводом
pixi run -e test python -m pytest tests/ -v

# Пропустить отладочные тестовые файлы
pixi run -e test python -m pytest tests/ -k "not debug"
```

Для просмотра сообщений лога при запуске тестов:

```bash
pixi run -e test python -m pytest tests/your_test_file.py -v -s
```
