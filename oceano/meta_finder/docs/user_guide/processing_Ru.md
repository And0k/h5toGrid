# Руководство по обработке

Описание того, как meta_finder обнаруживает устройства, извлекает метаданные и генерирует вывод.

## Pipeline обработки

Основной pipeline обработки (`collect.process_all_metadata()`) follows следующие stages:

1. **Обнаружение директорий экспедиций**: Сканирование настроенных директорий для директорий экспедиций, используя паттерн `YYMMDD_{cruise_name}`.

2. **Обнаружение директорий устройств**: Для каждой директории экспедиции, идентифицировать поддиректории устройств, используя `find_device_dirs()`, который соответствует:
   - Ключевые слова устройств: `inclinometer`, `incl`, `tcm`, `wavegauge`, `wave_gauge`, `pres`, `@i[0-9]`
   - Типы устройств (`i`, `w`, `incl`, `wg`) когда за ними следует запятая, точка с запятой или конец строки
   - Сама директория экспедиции, если её имя содержит идентификаторы устройств и нет поддиректорий устройств
   - Дата-именованные поддиректории (6-значный формат), если они существуют и нет других поддиректорий устройств

3. **Обнаружение файлов метаданных**: В каждой директории устройств, искать файлы метаданных устройств в порядке приоритета:
   - Сначала пытается прочитать `info_devices@meta_finder.yaml`
   - Заменяет на `info_devices.yaml` (если JSON присутствует)
   - Наконец заменяет на `info_devices.json` (устаревший)

4. **Обнаружение файлов данных**: Для каждой директории устройств, обнаружить все доступные файлы данных, используя `discover_datafiles_for_all_dev_in_dev_dir()`, который:
   - Ищет директории `text_output` и архивы для файлов данных (`.tsv`, `.txt`, `.csv`)
   - Использует механизм fallback для извлечения идентификаторов устройств из имён поддиректорий, когда имена файлов не содержат информации об устройстве
   - Ищет файлы в директориях `_raw`, соответствующие шаблонам имён устройств
   - Включает HDF5 файлы (proc_noAvg, proc, raw), если включено извлечение HDF5
   - Создаёт отображение идентификаторов устройств на их связанные пути файлов данных

5. **Обнаружение файлов навигации**: Поиск `.gpx` навигационных файлов в поддиректориях `*navigation*` или `*map*` внутри директорий устройств и директорий экспедиций.

6. **Ассоциация и извлечение метаданных**: Использование `get_absent_meta()` для ассоциации устройств с файлами данных и извлечения временной информации:
   - Создание структуры данных устройств, содержащей метаданные и data_paths для всех найденных устройств
   - Получение приоритизированных источников данных для извлечения времени для каждого устройства, используя функцию `sort_data_paths()`
   - Попытка извлечь временные метаданные из приоритизированных источников данных до успеха, поддерживая как текстовые файлы, так и HDF5 файлы
   - Обновление метаданных устройств временной информацией, сохраняя все пути данных для каждого устройства

7. **Слияние метаданных JSON и файлов данных (сохранение на уровне полей)**:
   При извлечении метаданных из файлов данных, система следует политике **сохранить-если-валидно** для отдельных полей метаданных:
   - Значения метаданных из файлов **сохраняются**, когда извлечение из файлов данных возвращает значения-заполнители (`?`, `""`, `-`, `None`)
   - Только поля с валидными извлечёнными данными перезаписывают значения из файлов метаданных
   - Это обеспечивает, что существующие параметры burst (`burst_dt`, `bursts_t`) и временные диапазоны (`time_st`, `time_en`) не теряются, когда извлечение завершается неудачей или возвращает пустые значения

8. **Создание комментариев комбинированных файлов**: Специальные комментарии генерируются для устройств в комбинированных файлах данных, чтобы указать, какие устройства представлены в каждом файле.

9. **Извлечение координат из GPX как fallback**: Если координатные метаданные отсутствуют.

10. **Генерация вывода**: Создание двух выходных файлов в директории `meta`:
    - `meta/{yymmdd_HHMM}_files_TCM.tsv`: Список всех обработанных файлов, сгруппированных по экспедиции
    - `meta/{yymmdd_HHMM}_meta_TCM.tsv`: Табуляция-разделённая таблица с консолидированными метаданными для всех устройств

## Приоритеты обнаружения устройств

Система обнаруживает устройства через несколько методов со следующим подходом обработки для текстовых файлов вывода, которые приоритизируются на основе нескольких критериев:

1. **Приоритет интервала осреднения**: Файлы с меньшими интервалами осреднения (секунды бина) имеют более высокий приоритет (2с файлы приоритетнее над 600с файлами, которые приоритетнее над 7200с файлами)
2. **Файлы без информации об осреднении**: Файлы без информации об осреднении в их именах обрабатываются как имеющие настроенное значение осреднения по умолчанию (обычно 2.0001 секунды), позволяя им сортироваться нормально на основе этого значения
3. **Специфичность**: Выделенные файлы (для конкретных устройств) имеют более высокий приоритет, чем комбинированные файлы
4. **Число устройств**: Файлы с меньшим числом упомянутых устройств имеют более высокий приоритет
5. **Число несовпадающих устройств**: Файлы с меньшим числом устройств, не присутствующих в файлах метаданных, имеют более высокий приоритет

### Приоритет извлечения временных диапазонов

Для каждого обнаруженного устройства система извлекает начальную и конечную временную информацию из соответствующих файлов данных в этом порядке:

1. **Анализ имён файлов данных**: Первичный источник информации об устройстве из имён файлов text_output
2. **Поиск в сырой директории**: Вторичный источник, когда файлы text_output не найдены
3. **Поддержка HDF5/MAT**: Конечный fallback, когда text_output и сырые файлы недоступны

Система пропускает извлечение HDF5, когда временные метаданные уже доступны в файлах метаданных. Если файлы метаданных уже содержат значимую временную информацию (значения, которые НЕ являются заполнителями типа "?", "-", или пустых строк) для полей `time_st`, `time_en`, или `coef_date`, система сохранит существующие метаданные и пропустит потенциально трудоёмкий процесс извлечения HDF5.

## Множественные интервалы

Если устройство имеет несколько интервалов постановки (например, поднято и повторно установлено), файл метаданных использует вложенную структуру:

```yaml
i03:
  0: ["P1", 15, 0.5, ?, 54.7, 19.8, "2023-05-08 12:00:00", "2023-05-15 08:00:00", -, -, ""]
  1: ["P2", 20, 1.0, ?, 54.9, 20.1, "2023-06-01 10:00:00", "2023-06-10 14:00:00", 120, 600, ""]
```

В этом случае TSV-файл создаёт **отдельную строку для каждого интервала**. Ключ интервала (в примере `0`, `1`) соответствует названию постановки: по умолчанию - порядковый номер, начиная с 0.
