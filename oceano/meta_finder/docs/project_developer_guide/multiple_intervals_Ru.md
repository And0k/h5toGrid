# Обработка множественных интервалов

Резюме реализации обработки устройств с несколькими интервалами постановки.

## Проблема

Устройства с несколькими временными интервалами (представленные с суффиксами подчёркивания, например `i10`, `i10_`, `i10__`) обрабатывались некорректно. Система выводила одно и то же последнее время для всех интервалов в TSV-файле вместо показа правильного временного диапазона для каждого интервала.

**Пример проблемы:**
```yaml
"i10":
  0: ["", 85, 0, "⭡", 55.8940, 19.0899, "2018-10-17 16:30:00", "2018-10-18 07:15:00"]
  1: ["", 85, 0, "⭡", 55.8940, 19.0899, "2018-10-22T12:03:00", "2018-10-27T06:47:28"]
```

**Некорректный вывод:**
```
ABP44	i10		85	0	55.894	19.0899	2018-10-17 16:30:00	2018-10-27 06:47:26	...
ABP44	i10_		85	0	55.894	19.0899	2018-10-22 12:03:00	2018-10-27 06:47:28	...
```

**Ожидаемый вывод:**
```
ABP44	i10		85	0	55.894	19.0899	2018-10-17 16:30:00	2018-10-18 07:15:00	...
ABP44	i10		85	0	55.894	19.0899	2018-10-22 12:03:00	2018-10-27 06:47:28	...
```

## Решение

Трёхуровневый подход:

1. **Слой чтения метаданных** ([`io_info_files.py`](../../src/meta_finder/io_info_files.py)): Выравнивание множественных интервалов на этапе чтения метаданных путём преобразования устройств с суффиксами подчёркивания в одну запись устройства со списком `intervals`

2. **Слой обработки** ([`collect.py`](../../src/meta_finder/collect.py)): Обновление логики извлечения времени для работы с новой структурой интервалов

3. **Слой вывода** ([`file_writer.py`](../../src/meta_finder/file_writer.py)): Изменение TSV-записчика для создания одной строки на интервал с корректными временными значениями

## Детали реализации

### Слой чтения метаданных (`io_info_files.py`)

Модифицирован `_ungroup_devices_with_underscore_suffixes` для:
- Обнаружения устройств с множественными интервалами (несколько суффиксов подчёркивания для одного базового имени)
- Создания списка `intervals`, содержащего временно-специфичные данные для каждого интервала
- Извлечения не-временных полей (sea_depth, lat, lon и т.д.) из базового устройства
- Обработки форматов list/tuple и dict для метаданных устройств

### Слой обработки (`collect.py`)

Модифицирован `update_device_metadata_with_time_info` для:
- Проверки, имеет ли устройство структуру `intervals`
- Обновления временных полей в первом интервале для устройств с множественными интервалами
- Обновления временных полей напрямую в записи устройства для устройств с одним интервалом
- Обновления полей только когда извлечённые значения не являются заполнителями

### Слой вывода (`file_writer.py`)

Модифицирован `write_metadata_table` для:
- Проверки, имеет ли устройство список `intervals`
- Создания одной строки TSV на интервал для устройств с множественными интервалами
- Копирования не-временных полей из метаданных устройства в каждую строку интервала
- Копирования `data_paths` из устройства в каждую строку интервала
- Добавления поля `interval_index` для отслеживания номера интервала

## Классификация полей

### Временные поля (варьируются для каждого интервала)
- `time_st` — Время начала
- `time_en` — Время конца
- `burst_dt` — Время burst
- `bursts_t` — Период burst
- `coef_date` — Дата коэффициентов
- `time_raw_st` — Время начала сырых данных
- `time_raw_en` — Время конца сырых данных

### Не-временные поля (общие для всех интервалов)
- `point` — Идентификатор точки
- `sea_depth` — Глубина моря
- `height_above_bottom` — Высота над дном
- `modification_symbol` — Символ модификации
- `lat` — Широта
- `lon` — Долгота
- `comment` — Комментарий

## Обратная совместимость

Реализация сохраняет полную обратную совместимость:
- Устройства с одним интервалом продолжают работать как раньше
- YAML-файлы с суффиксами подчёркивания автоматически преобразуются в структуру intervals
- Существующий формат TSV вывода сохраняется для устройств с одним интервалом
- Изменения в существующих YAML-файлах не требуются
