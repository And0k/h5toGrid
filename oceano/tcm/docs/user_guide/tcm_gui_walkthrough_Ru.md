# Пошаговый пример работы в программе `tcm_gui`

Запуск обработки данных инклинометра в окне программы: выбрать данные, внести поправку
на магнитное склонение, запустить обработку. Текстовый файл-результат.

> Рассматривается **упрощённый режим** (запуск без удержания **Shift**) в сборке
> **noh5** («без HDF5»). В этом сочетании на выходе получаются **только текстовые**
> файлы (и YAML-конфигурации) — бинарные данные `.nc`/`.h5` не создаются и не читаются,
> данные по умолчанию выводятся без усреднения в полном разрешении.

Окно `tcm_gui.exe` сверху вниз, слева направо устроено так:

| Часть окна | Что находится |
|---|---|
| Поле пути | строка ввода пути к данным + кнопки выбора |
| Строка заголовка/статуса | текущая стадия, общий процент |
| Вертикальный рейл слева | колонка прогресса + вкладки (вкладка = один файл конфигурации, обычно — прибор, см. [раздел 1](#1-выбор-данных)) |
| Таблица параметров | конфигурация в виде дерева настроек (входные данные, коэффициенты) и метаданные прибора |
| Нижняя область | протокол, строка состояния |

Имена файлов и приборов в примерах — канонические (например `i05`, `i_p05`), как их
пишет сама программа. Содержание:

1. [Выбор данных](#1-выбор-данных)
2. [Ввод поправки магнитного склонения](#2-ввод-поправки-магнитного-склонения)
3. [Процесс обработки](#3-процесс-обработки)
4. [Выходные данные и текстовый файл](#4-выходные-данные-и-текстовый-файл)

## 1. Выбор данных

В верхнем поле необходимо напечатать путь к данным и нажать **Enter**
либо выбирать папку/файлы кнопкой справа, меняющейся в зависимости от нажатия **Shift**:

| Кнопка | Действие |
|---|---|
| **Каталог…** | выбор папки; программа сама проводит поиск данных |
| удерживая **Shift**: **Файлы…** | выбор файлов с разрешенными расширениями |

В поле можно ввести:

- **Путь к папке с исходными данными**, например
  `D:\Данные\Рейс12\incl_05\_raw`. `_raw` — это не требование, а рекомендуемое имя —
  если каталога `_raw` в пути нет, то необходимо условие: в папке **лежат сами файлы
  данных (`i05.txt`, `INKL_090.TXT`, …)**. Если папка названа «_raw», то поиск будет и
  в ее дочерних папках. Если поиск ничего не найдёт, то поле станет красным (тогда
  введите путь к папке, где файлы лежат, или к родителю содержащему
  папкy/папки `_raw`). Для краткости далее обозначаем `_raw` такой каталог или
  каталог с именем «_raw».
- **Путь к родительской папке экспедиции** — программа найдёт все папки `_raw`
  приборов, а их список появится в выпадающем списке поля (первая выбрана
  автоматически, остальные — в один клик);
- **Путь по шаблону** (например `*i*.txt`) — выбрать группу файлов по имени;
- **Путь к файлу конфигурации** (имя заканчивается на `.yaml`) — открыть ранее
  созданные настройки напрямую, без повторного поиска данных.

Конфигурации `cfg_proc` программа создаёт **внутри `_raw`**.

Папку выходных файлов `text_output` программа выбирает по своим правилам —
ближайшую выше по пути папку, имя которой начинается с даты или равно `inclinometer`
(при стандартном `_raw` — просто рядом с ним).

**Что делает программа.** Определяет приборы по именам файлов (первая буква `i` —
инклинометр, `w` — волномер) и для каждого прибора создаёт (а если есть — открывает)
его файл конфигурации в `cfg_proc/run/` внутри папки `_raw`. **Вкладка — это одна
конфигурация**: обычно у прибора одна конфигурация, но если он работал
несколько раз (с другим набором файлов) —
конфигураций, а значит и вкладок, у него будет несколько. (Вы также можете сами добавлять файлы конфигураций с другими  коэффициентами или параметрами обработки, например других интервалами и все они будут загружены). Читает необязательный журнал
установки `info_devices.yaml`: время работы прибора, интервалы включения, который вы можете
дополнять. Ошибочные пути показываются красным шрифтом.

**Результат на экране.** Список вкладок-конфигураций. В каждой вкладке — «дерево»
параметров, которое раскрывается (▸) и сворачивается (▾):

Меню на вкладке правой кнопкой мыши *`Убрать`* и *`Отключить`*: убирает вкладку или исключает её из обработки при *`Запуске`*. Новый поиск сбрасывает все отключения.

- `input.path` — путь к исходному файлу данных;
- `input.time_ranges` — окно времени, которое будет обработано;
- `input.coefs` — калибровочные коэффициенты;
- `input.calib` — пункты пересчёта коэффициентов (см. [поправку склонения](#2-ввод-поправки-магнитного-склонения)).
- `metadata` — журнал установки (станция, глубины, координаты, интервал работы, паузы);

Наведите курсор на любую строку — в строке состояния появится короткая подсказка,
при задержке курсора — подробная; **F1** открывает справочник полей.

## 2. Ввод поправки магнитного склонения

Магнитное склонение — угол между направлением на географический и на магнитный север
в точке установки, который нужно добавлять к результату измерения азимута. Задается
корректировкой текущего калибровочного коэффициента `input.coefs.azimuth_shift_deg`
напрямую или через добавление поправки `input.calib`:

### Вариант А: по координатам станции

В [`input.calib`](../reference/config_reference_Ru.md#inputcalib) есть строка [**`coordinates`**](../reference/config_reference_Ru.md#inputcalibcoordinates) — пара чисел (широта, долгота).
Напротив строки стоит отметка-«флажок» ☑ — признак мгновенного пересчёта.

1. Двойным щелчком по ячейке войдите в редактирование.
2. Введите через запятую два числа — широту и долготу станции в градусах
   (например: `54.95, 19.85`).
3. Нажмите **Enter**.

**Что делает программа.** Сразу, ещё до запуска обработки, по модели геомагнитного
поля (координаты + дата измерений) вычисляется магнитное склонение станции и
добавляется к азимутальной поправке — в протоколе появляется сообщение вида:

```
Coefs prepared: with manual azimuth adjustment (coordinates)
```

Нажав ☑ вы сразу добавляете сдвиг направления к текущему коэффициенту поправки
`input.coefs.azimuth_shift_deg` — [сдвиг азимута](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift); после нажатия **Run** (см. [процесс обработки](#3-процесс-обработки)) в файлы попадут
данные пересчитанные с его учетом. Иначе - это все равно произойдет во время обработки.


### Вариант Б: вручную — углом сдвига

Если вы знаете склонение сами (или модель не подходит), введите [**`azimuth_add`**](../reference/config_reference_Ru.md#inputcalibazimuth_add) —
число в градусах со знаком. Оно будет сложено с поворотом из данных. Оба поля можно
использовать вместе: координаты и добавочный угол дадут суммарную поправку.

Если вы несколько раз нажимали ☑ все изменения аккумулируются. **Проверьте**:
раскройте `input.coefs.azimuth_shift_deg` (по умолчанию ≈`180`°) перед запуском.

## 3. Процесс обработки

Нажимаете кнопку **«Run»** (внизу окна). Во время работы она становится кнопкой паузы:
повторное нажатие приостанавливает обработку, ещё одно — продолжает.

**Что показывает программа:**

- **Вертикальный рейл слева**: у каждой вкладки своя вертикальная полоса прогресса,
  выровненная по конфигурации (этапы: загрузка → коэффициенты → обработка → вывод).
  По полосе видно, какая конфигурация сколько сделала.
- **Строка статуса сверху**: общий процент по всем конфигурациям и текущая стадия
  обработки (загрузка / коэффициенты / обработка / сохранение…). Эта полоса — одна,
  горизонтальная, и показывает текущую подзадачу.
- **Протокол** — сообщения в реальном времени (цвет — уровень важности). Пути к
  файлам в сообщениях кликабельны: клик открывает файл.
- **Строка состояния (внизу)** — имя текущего этапа; по завершении — «Done — N%».

**Что происходит за кулисами** (по шагам — чтобы свериться с протоколом):

1. **Сохранение.** Отредактированные коэффициенты **только включённых** вкладок записываются в YAML-конфигурацию
   прибора (`cfg_proc\run\@i05.yaml`); перед записью создаётся резервная копия с
   отметкой времени (например, `backup260625_012101.yaml`). Убранные и отключённые вкладки пропускаются.
2. **Прогон по каждой включённой вкладке.**
   - чтение исходного файла;
   - подготовка коэффициентов (применяется и [поправка склонения](#2-ввод-поправки-магнитного-склонения));
   - вычисление физических величин: скорости (север/восток), наклона, давления;
   - запись результата в текстовый файл ([выходные данные](#4-выходные-данные-и-текстовый-файл)).
3. **Итог** — в протоколе строка вида:

```
Done — N probes: i05 OK
```

Если прибор не обработан — его имя будет помечено (`failed` или `skipped`), а в
протоколе появится пояснение (например, «нет данных в интервале», «файл не
найден»). Предупреждения подсвечены жёлтым — их стоит прочитать.

**Результат.** Повторный **Run** с теми же данными и настройками дополняет результат
(не портит и не пересоздаёт уже созданные файлы).

## 4. Выходные данные и текстовый файл

### Где лежат результаты

Ниже — стандартная схема, когда папка исходников называется `_raw` (в ней лежат
файлы вида `i05.txt`), как в [разделе о выборе данных](#1-выбор-данных). При другом имени папки размещение меняется
по правилам раздела о выборе данных: `cfg_proc` окажется внутри выбранной папки, `text_output` —
в папке, выбранной программой; готовые пути видны в протоколе. После обработки
структура папок такая (пример):

```text
D:\Данные\Рейс12\
└── incl_05\                        ← каталог прибора
    ├── _raw\                       ← исходные файлы (i05.txt, …)
    │   ├── @i05.txt                ← служебная копия исходника с каноническим именем
    │   └── cfg_proc\
    │       ├── run\                ← YAML-конфигурации приборов (правятся через окно)
    │       └── log\                ← журналы и протокол обработки
    ├── info_devices.yaml           ← журнал установки: станция, глубины, интервалы
    └── text_output\                ← ТЕКСТОВЫЕ РЕЗУЛЬТАТЫ — рядом с _raw
        └── 260624_1500@i05.tsv     ← результат обработки прибора i05
```

| Что появляется | Где | Зачем |
|---|---|---|
| `text_output\{момент}@{прибор}.tsv` | `text_output\` рядом с `_raw` | **главный результат** — данные по времени |
| `@i05.txt` | в `_raw\` | служебная копия исходника с каноническим именем |
| `cfg_proc\run\@i05.yaml` | в `_raw\` | конфигурация прибора; сюда записываются коэффициенты (в т.ч. поправка) |
| `info_devices.yaml` | рядом с `_raw` | журнал установки прибора (вкладка metadata) |
| `cfg_proc\log\` | в `_raw\` | журнал обработки — копия сообщений протокола |

> В сборке **noh5** бинарные файлы (`*.raw.nc`, `*.proc_*.nc`) **не создаются** —
> только текст и YAML. Упрощённый режим даёт вывод в **полном разрешении** (без
> усреднения по интервалам): каждый отсчёт исходника — отдельная строка таблицы.

### Текстовый файл-результат подробно

Файл `…\text_output\260624_1500@i05.tsv` — таблица, где **каждая строка — один
отсчёт (момент времени)**; столбцы разделены знаком табуляции (отсюда суффикс
`tsv`), а названия столбцов стоят в первой строке. Файл открывается любым
текстовым редактором; удобно строить графики и фильтры в Excel (импорт текста,
разделитель — табуляция).

Пример заголовка `*.tsv` со строкой данных из файла (табуляция заменена на пробелы для наглядности):


```text
Time                       v        u         inclination Temp  Pressure Vabs   Vdir
2024-08-13 15:16:44.000000 -0.11271 -0.079116 14.51       19.12 14.044   0.1377 -144.93
```

Состав столбцов:

| Колонка | Единицы | Что означает | Откуда данные |
|---|---|---|---|
| `Time` | — | момент измерения, формат `YYYY-MM-DD HH:MM:SS.SSSSSS` | часы прибора |
| `v` | м/с | скорость — составляющая на север | расчёт из наклона |
| `u` | м/с | скорость — составляющая на восток | расчёт из наклона |
| `inclination` | ° | угол наклона прибора от вертикали | расчёт ([наклон и азимут](../methodology/velocity_Ru.md#наклон-и-азимут)) |
| `Pressure` | м | глубина прибора (давление столба воды) | расчёт по коэффициентам [`P_t`](../reference/config_reference_Ru.md#inputcoefsp_t) (если заданы) |
| `Temp` | °C | температура | из исходного файла (если датчик есть) |
| `Vabs` | м/с | модуль скорости течения √(`v`²+`u`²) | всегда в тексте |
| `Vdir` | ° | направление течения (азимут наклона с поправкой `azimuth_shift_deg`) | [расчёт](../methodology/velocity_Ru.md#сдвиг-азимута-psitextshift) из акселерометра и магнетометра |


- **Время** — по часам прибора.
- **Знаки компонент.** Отрицательный `v` — течение на юг, отрицательный `u` — на
  запад. `v<0, u≈0` — течение точно на юг, `u>0` — на восток.
- **Направление `Vdir`** отсчитывается по часовой стрелке от севера ([сдвиг азимута](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift)) и показывает **куда течёт** вода.
- Поправка склонения уже включена в направление и компоненты скорости
- Колонки `Pressure` и `Temp` появляются только если таких данные есть в исходнике.


Подробная спецификация текстового вывода — [Input / Output Format
Specification](../reference/io_formats.md#output-tsv-files) ([раздел «Output TSV files»](../reference/io_formats.md#output-tsv-files)); связь
скорости с наклоном и поворот направления — [Вычисление скорости течения по
данным акселерометра и магнетометра](../methodology/velocity_Ru.md).

### Реализовано также, но не раскрыто в этом руководстве

- **Калибровка вертикали (zeroing)** — поворот `Rz`, чтобы ось Z датчика совпала с
  вертикалью. Задаётся вектором [`input.calib.g0xyz`](../reference/config_reference.md#inputcalibg0xyz)
  (одно известное показание акселерометра) или интервалом
  [`input.calib.time_ranges_zeroing`](../reference/config_reference.md#inputcalibtime_ranges_zeroing)
  (прибор висит вертикально). См.
  [Обновление коэффициентов через zeroing](../user_guide/configuration.md#updating-coefficients-via-zeroing).
- **Калибровка азимута по данным** — интервал
  [`input.calib.time_ranges_azimuth`](../reference/config_reference.md#inputcalibtime_ranges_azimuth):
  прибор наклонён в известном направлении, программа вычисляет `azimuth_shift_deg`.
  Описано в разделе
  [Updating coefficients via zeroing](../user_guide/configuration.md#updating-coefficients-via-zeroing).
- **Калибровочные коэффициенты** — `Ag`, `Cg`, `Ah`, `Ch`, `Rz`, `kVabs`, `P` в
  [`input.coefs`](../reference/config_reference.md#inputcoefs--calibration-coefficients);
  источник коэффициентов (`input.coefs.path`) отображается прямо в строке `coefs`
  (parent node). См. [Calibration coefficients](../user_guide/configuration.md#calibration-coefficients).
