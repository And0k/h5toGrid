# Правила создания документации

Требования к документам Markdown, чтобы они отображались одинаково во встроенном просмотр документации вы можете запустить по ссылкам в окне по кнопке "?" → "О программе" (реализовано в "tcm_gui/browser/") и на
GitHub. Средство просмотра полностью работает в автономном режиме: размеченные (GFM CommonMark) + MathJax 4 +
highlight.js являются встроенными (генерируются в `_build/browser-runtime` с помощью
`browser/vendor.mjs`); ничего не загружается из Интернета.

## Математические выражения

| Форма | Разделители | Использование |

|---|---|---|

| Встроенные | `\( ... \)` | математические выражения внутри текста: `\(E = mc^2\)` |

| Отображение | `$$ ... $$` или `\[ ... \]` | отдельные блоки уравнений (пустая строка до/после) |

- Символ доллара `$...$` **намеренно отключен** (знаки доллара распространены в
обычном тексте) — он отображается буквально.

- **Никогда** не оставляйте математические выражения ASCII в тексте: `h = A^-1 (F u) + b`, `S^2`, `sum_i`
отображаются дословно. Преобразуйте в TeX: `\(h = A^{-1} (F u) + b\)`.

- TeX внутри блоков кода/ограждений остается буквальным (просмотрщик сначала защищает код) —
используйте блок кода, когда буквальные символы являются точкой.

- `\(...\)` и `\[...\]` безопасны в тексте: просмотрщик защищает блоки математических выражений от
удаления экранирования обратной косой черты CommonMark перед анализом.

- Предпочитайте `\text{}` для слов внутри формул; Поддерживаются `\mathbb{R}`, `\lfloor\rfloor`,

`\begin{cases}` (полный TeX через MathJax).

## Код

- Блоки кода с отступами **всегда с тегом языка** — тег управляет highlight.js:

````markdown
```python
def f(x): ...
```
````

Поддерживаемые теги: `python`, `bash`, `powershell`, `dos`, `yaml`, `json`,

`toml`, `ini`, `text` (без подсветки — выравнивание безопасно для ASCII-диаграмм,
деревьев, табличных трассировок).

- **Без блоков кода с отступами (4 пробела)**: CommonMark отображает их, но без
подсветки, и они неоднозначны при продолжении списка. Они также являются
классической ловушкой при вставке математических формул — уравнение с отступом в 4 пробела незаметно превращается в
моноширинный блок вместо отображаемой формулы. Используйте блоки или `$$`.

- Встроенные идентификаторы в обратных кавычках: `solve_optimal_weights`, `input.path`.

## Ссылки

- **Относительно собственного каталога документа** — средство просмотра обращается к
местоположению файла, а не к корневому каталогу сервера. Из `docs/reference/`:

| Цель | Ссылка |

|---|---|

| соседний документ | `config_tuning.md` |

| другой раздел | `../user_guide/processing.md` |

| исходный код пакета | `../../src/tcm/format.py` |

| скрипты сборки | `../../scripts/tcm_proc.py` |

Исходный код находится в `src/tcm/` — `../../tcm/x.py` не существует (историческая
партия таких ссылок, выдающих ошибку 400 в программе просмотра).

- **Якоря заголовков**: URL-адреса GitHub — строчные буквы, знаки препинания опущены, каждый пробел
→ `-`; или явный суффикс `{#my-id}` в заголовке. Межфайловый анализ:

`io_formats.md#file-name-parsing`.

- **Якоря строк исходного кода**: `file.py#L42` прокручивает представление исходного кода до строки 42.

## Изображения

Относительный путь к любому настроенному типу изображения (png, jpg, gif, webp, svg, bmp,
avif): `![calibration flow](images/flow.png)`. Размещается рядом с документацией (или в соседней директории `images/`), чтобы GitHub и средство просмотра одинаково их обрабатывали.

## Классы файлов, доступные для просмотра

| Класс | Расширения |

|---|---|

| markdown | `.md`, `.markdown` |

| source/text | `.py`, `.js`, `.ts`, `.yaml`, `.toml`, `.ini`, `.txt`, `.log`, `.sh`, `.ps1`, `.bat` … |

| images | см. выше |

Все остальное не отображается — ссылки только на эти классы.

## Самопроверка

Откройте документ через средство просмотра (О программе → Дерево документации или любую ссылку на документ в нем) и проверьте: каждая формула набрана правильно (нет буквальных `\(` / `^` в тексте), каждый блок кода выделен, каждая локальная ссылка ведет без ошибок 400/404, кнопка «Назад» возвращает на место.

> **Разделы с подробной информацией о полях** — Когда значение поля зависит от контекста (обработка для каждого зонда или спецификация входных данных), ячейка таблицы остается минимальной, а подробная документация помещается в подразделы `###`, помеченные **режимом**:
>
> | Режим | Режим содержимого | Пример потребителя |
> |------|---------------|------------------|
> | `<mode>зонд</mode>` | Значение обработки для каждого зонда — что делает поле, как оно влияет на результаты | Наведение курсора на коэффициент в графическом интерфейсе, всплывающее окно |
> | `<mode>search</mode>` | Шаблоны спецификации входных данных — glob, regex, directory, YAML | Поле пути GUI, справка CLI |

>
> GUI сравнивает свой текущий контекст с тегом `<mode>` и выбирает соответствующее
> содержимое. Добавьте новые режимы в качестве подзаголовков `### \`field.path\` <mode>value</mode>`;

> парсер распознает любое значение `[a-z_]+`. Ограничьте ячейки таблицы одним предложением.

>
> Подробные тела (`###`/`####`) не зависят от интерфейса: нет имен виджетов GUI, нет
> обрамления аргументов CLI — контекст потребителя выражается только тегами `<mode>`.

# Разделы детализации полей в config_reference.md для возможности программного отображения в status и tooltip

Ячейки таблиц — одно лаконичное предложение (используется в GUI status messages),
более подробная документация — пояснения в подразделах `###` (используется в GUI tooltips).
Когда смысл поля зависит от контекста, подразделы `###` указываются с **режимом**:


| Режим | Контент | Пример потребителя |
|-------|---------|-------------------|
| `<mode>probe</mode>` | Смысл при обработке конкретного зонда — что делает поле, как влияет на результат | Hover в ячейках конфига GUI, во всплывающем окне |
| `<mode>search</mode>` | Паттерны входных данных — glob, regex, директория, YAML | Поле пути GUI, справка CLI |

GUI сравнивает текущий контекст с тегом `<mode>` и выбирает соответствующий контент.
Добавляйте новые режимы как подзаголовки `### \`field.path\` <mode>value</mode>`;
парсер распознаёт любое значение `[a-z_]+`.

Тела режимов (`###`/`####`) интерфейсно-нейтральны: без имён виджетов GUI и без
привязки к аргументам CLI — контекст потребителя выражается только тегами `<mode>`.
