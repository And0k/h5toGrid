# STATUS: IMPLEMENTED — see simplified structure below

Adopted the npm-as-lockfile-manager design with a simpler, subsystem-owned
layout than the original proposal:

```
tcm/
├── browser/                     npm subsystem (owns the whole chain)
│   ├── package.json             committed exact pins
│   ├── package-lock.json        committed lock
│   └── vendor.mjs               sync/update/clean automation + file map
├── src/tcm_gui/browser/         Python: __init__.py, browser.py, server.py, web/
│   └── web/                     first-party viewer (index.html, viewer.js, viewer.css)
├── _build/browser-runtime/      generated third-party runtime (git-ignored)
```

- `_build/browser-runtime/` is generated by `browser/vendor.mjs` (`npm ci` + copy
  of the minimal file map) and excluded from Git (`**/_build/`, `**/node_modules/`).
- Pixi tasks `browser-runtime` (auto-materialize; dependency of `build-tcm-gui*`)
  and `browser-runtime-update` (manual bump to `@latest`); `lock`/`clean` run the
  script directly. Node comes from the pixi `browser` feature (`bin-optim-tcm`).
- The viewer page was extracted from the old embedded f-string into
  `src/tcm_gui/browser/web/` plain files; the `bs`-escape machinery is gone.
  Third-party files are served under `/assets/` from `_build/browser-runtime`.
- Fixes landed with this change: .py/source files no longer render an empty page
  (panel visibility toggles `display:"block"`, not `""`); the source-language
  table is trimmed to repo-present types; `todo/` docs and unneeded files are
  excluded from the PyInstaller dist.
- Original proposal text below is kept for reference (it used `web/browser/`,
  `tools/browser_vendor.mjs`, `_build/browser-vendor`, whole-MathJax copy —
  superseded as above).

# The whole setup with using npm as the dependency/lockfile manager for the browser runtime, and use Pixi only to provide Node.js and orchestrate the npm step.
Do not maintain a second custom `vendor.toml`; npm's `package-lock.json` already records the exact dependency tree, `resolved` tarballs, and `integrity` values. npm explicitly recommends committing `package-lock.json` to source control for reproducible installs. ([npm Docs][1])

For the current packages, the npm registry currently reports marked 18.0.9, MathJax 4.1.3, and highlight.js 11.11.1. Marked's current package requires Node.js ≥20, so the Pixi environment should provide a modern Node LTS rather than an ancient Node runtime. ([npm][2])

The important ownership boundaries are now exact:

```text
src/.../browser/      your Python browser implementation
web/browser/src/      your HTML/CSS/JavaScript implementation
web/browser/*.json    npm dependency declaration + lock
tools/                automation
_build/               generated third-party runtime
docs/                 actual documentation
```

`web/browser/package-lock.json` is **committed**. `web/browser/node_modules/` is not. `_build/browser-vendor/` is not.

MathJax's official documentation specifically says that the bundled files from the npm package are what should be hosted on your own server; the combined `tex-chtml` component includes the default `mathjax-newcm` font, with additional font data potentially loaded dynamically. ([MathJax Documentation][3])

## 1. `web/browser/package.json`

Do not manually write `package-lock.json`. Write this `package.json`, then let npm generate the lockfile.

```json
{
  "name": "tcm-browser",
  "private": true,
  "version": "0.0.0",
  "description": "Browser runtime for the tcm local documentation viewer",
  "engines": {
    "node": ">=20"
  },
  "dependencies": {
    "highlight.js": "11.11.1",
    "marked": "18.0.9",
    "mathjax": "4.1.3"
  }
}
```

The versions above are the current versions reported by npm at the time of this answer. ([npm][2])

Use **exact versions**, not `^18.0.9` or `~18.0.9`. `package-lock.json` already gives you the exact resolved tree, but exact top-level versions make the intent obvious and make `npm update` an explicit operation.

## 2. Generate `package-lock.json`

From the subproject root:

```text
pixi install
pixi run browser-lock
```

The first implementation of `browser-lock` below runs `npm install --package-lock-only`, so it creates the lock without leaving a dependency installation as a prerequisite.

After that, commit:

```text
web/browser/package.json
web/browser/package-lock.json
```

The lockfile contains records such as:

```json
{
  "node_modules/marked": {
    "version": "18.0.9",
    "resolved": "https://registry.npmjs.org/marked/-/marked-18.0.9.tgz",
    "integrity": "sha512-..."
  }
}
```

That `resolved` + `integrity` pair is exactly the information we were previously trying to recreate manually in `vendor.toml`; npm already maintains it. ([npm Docs][1])

## 3. `tools/browser_vendor.mjs`

This is the only custom Node automation.

It has four operations:

```text
lock     create/update package-lock metadata
sync     npm ci + copy runtime files into _build/browser-vendor
update   explicitly update the three top-level packages
clean    remove generated browser runtime
```

```javascript
/**
 * Browser-runtime dependency automation.
 *
 * Repository:
 *
 *     web/browser/package.json
 *     web/browser/package-lock.json
 *
 * Generated:
 *
 *     web/browser/node_modules/
 *     _build/browser-vendor/
 *
 * `package-lock.json` is the authoritative lockfile. npm itself records:
 *
 *     version
 *     resolved
 *     integrity
 *
 * for the exact dependency tree.
 *
 * Commands:
 *
 *     node tools/browser_vendor.mjs lock
 *     node tools/browser_vendor.mjs sync
 *     node tools/browser_vendor.mjs update
 *     node tools/browser_vendor.mjs clean
 *
 * Normally these are invoked through Pixi:
 *
 *     pixi run browser-lock
 *     pixi run browser-vendor
 *     pixi run browser-vendor-update
 *     pixi run browser-vendor-clean
 *
 * `sync` uses `npm ci`, not `npm install`.
 *
 * Therefore:
 *
 *     package.json + package-lock.json
 *                    |
 *                    v
 *                 npm ci
 *                    |
 *                    v
 *             exact node_modules
 *                    |
 *                    v
 *          selected browser runtime
 *
 * npm verifies the lockfile-resolved artifacts during installation.
 */

import { execFileSync } from "node:child_process";
import { cpSync, existsSync, mkdirSync, readFileSync, rmSync } from "node:fs";
import { dirname, join, resolve } from "node:path";
import { fileURLToPath } from "node:url";


const PROJECT_ROOT = resolve(
    dirname(fileURLToPath(import.meta.url)),
    "..",
);

const BROWSER_ROOT = join(
    PROJECT_ROOT,
    "web",
    "browser",
);

const BROWSER_SOURCE = join(
    BROWSER_ROOT,
    "src",
);

const NODE_MODULES = join(
    BROWSER_ROOT,
    "node_modules",
);

const VENDOR_ROOT = join(
    PROJECT_ROOT,
    "_build",
    "browser-vendor",
);


const NPM = process.platform === "win32"
    ? "npm.cmd"
    : "npm";


function run(command, args) {
    console.log(
        `[browser-vendor] ${command} ${args.join(" ")}`,
    );

    execFileSync(
        command,
        args,
        {
            cwd: BROWSER_ROOT,
            stdio: "inherit",
        },
    );
}


function ensureDirectory(path) {
    mkdirSync(path, {
        recursive: true,
    });
}


function packagePath(packageName) {
    return join(
        NODE_MODULES,
        ...packageName.split("/"),
    );
}


function installExactDependencies() {
    /*
     * npm ci:
     *
     * - requires package-lock.json,
     * - installs the exact locked tree,
     * - removes an existing node_modules first,
     * - does not modify package.json or package-lock.json.
     *
     * --ignore-scripts avoids executing arbitrary lifecycle scripts from
     * downloaded packages. These three browser libraries do not need their
     * install scripts for the browser runtime we use.
     */
    run(NPM, [
        "ci",
        "--omit=dev",
        "--ignore-scripts",
        "--no-audit",
        "--no-fund",
    ]);
}


function copyClean(source, destination) {
    rmSync(destination, {
        recursive: true,
        force: true,
    });

    cpSync(
        source,
        destination,
        {
            recursive: true,
        },
    );
}


function syncMarked() {
    const source = join(
        NODE_MODULES,
        "marked",
        "lib",
        "marked.umd.js",
    );

    if (!existsSync(source)) {
        throw new Error(
            `Marked browser bundle not found: ${source}`,
        );
    }

    const destination = join(
        VENDOR_ROOT,
        "marked",
        "marked.umd.js",
    );

    ensureDirectory(
        dirname(destination),
    );

    cpSync(
        source,
        destination,
    );
}


function syncMathJax() {
    const source = packagePath(
        "mathjax",
    );

    if (!existsSync(source)) {
        throw new Error(
            `MathJax package not found: ${source}`,
        );
    }

    /*
     * Do not cherry-pick MathJax's files.
     *
     * Its combined components may load additional font/data files. The
     * official self-hosting documentation treats the npm package/bundle as
     * the runtime tree to serve.
     */
    copyClean(
        source,
        join(
            VENDOR_ROOT,
            "mathjax",
        ),
    );
}


function syncHighlightJs() {
    const sourceScript = join(
        NODE_MODULES,
        "highlight.js",
        "lib",
        "common.min.js",
    );

    const sourceStyle = join(
        NODE_MODULES,
        "highlight.js",
        "styles",
        "default.min.css",
    );

    if (!existsSync(sourceScript)) {
        throw new Error(
            `highlight.js browser bundle not found: ${sourceScript}`,
        );
    }

    if (!existsSync(sourceStyle)) {
        throw new Error(
            `highlight.js stylesheet not found: ${sourceStyle}`,
        );
    }

    const destination = join(
        VENDOR_ROOT,
        "highlight.js",
    );

    ensureDirectory(destination);

    cpSync(
        sourceScript,
        join(
            destination,
            "highlight.min.js",
        ),
    );

    cpSync(
        sourceStyle,
        join(
            destination,
            "default.min.css",
        ),
    );
}


function sync() {
    /*
     * This removes stale files from an older browser-runtime version.
     */
    rmSync(
        VENDOR_ROOT,
        {
            recursive: true,
            force: true,
        },
    );

    ensureDirectory(
        VENDOR_ROOT,
    );

    installExactDependencies();

    syncMarked();
    syncMathJax();
    syncHighlightJs();

    /*
     * Copy the first-party browser source separately from third-party files.
     * This is useful both for local development and for PyInstaller.
     */
    if (!existsSync(BROWSER_SOURCE)) {
        throw new Error(
            `Browser source directory does not exist: ${BROWSER_SOURCE}`,
        );
    }

    console.log(
        "[browser-vendor] runtime synchronized",
    );
}


function lock() {
    /*
     * package-lock-only updates metadata while avoiding a full installation.
     *
     * This is useful after changing package.json manually.
     */
    run(NPM, [
        "install",
        "--package-lock-only",
        "--ignore-scripts",
        "--no-audit",
        "--no-fund",
    ]);
}


function update() {
    /*
     * Explicitly request the current stable top-level releases.
     *
     * --save-exact changes package.json from a range to the exact release.
     *
     * npm then updates package-lock.json and records the resulting resolved
     * tarballs and integrity values, including any changed transitive tree.
     */
    run(NPM, [
        "install",
        "--save-exact",
        "--ignore-scripts",
        "--no-audit",
        "--no-fund",
        "marked@latest",
        "mathjax@latest",
        "highlight.js@latest",
    ]);

    /*
     * The install above has already produced node_modules. Re-run sync so the
     * generated application vendor directory is rebuilt from that exact lock.
     */
    sync();
}


function clean() {
    rmSync(
        NODE_MODULES,
        {
            recursive: true,
            force: true,
        },
    );

    rmSync(
        VENDOR_ROOT,
        {
            recursive: true,
            force: true,
        },
    );

    console.log(
        "[browser-vendor] generated files removed",
    );
}


const command = process.argv[2] ?? "sync";

switch (command) {
    case "lock":
        lock();
        break;

    case "sync":
        sync();
        break;

    case "update":
        update();
        break;

    case "clean":
        clean();
        break;

    default:
        console.error(
            "Usage: browser_vendor.mjs {lock|sync|update|clean}",
        );
        process.exitCode = 2;
}
```

The important design improvement over the previous Python downloader is that **npm, not your code, is responsible for dependency resolution and integrity verification**. `npm ci` is specifically intended for automated/reproducible installs from a lockfile and will fail if `package.json` and `package-lock.json` are inconsistent. ([npm Docs][4])

## 4. `pixi.toml`

Add Node.js to the **same Pixi environment as your Python development environment**. Do not create another environment just for the viewer.

The relevant part is:

```toml
[dependencies]
python = "3.12.*"
nodejs = ">=20,<25"

[tasks]

# ---------------------------------------------------------------------------
# npm metadata
# ---------------------------------------------------------------------------

browser-lock = {
    cmd = "node tools/browser_vendor.mjs lock",
    inputs = [
        "web/browser/package.json",
        "tools/browser_vendor.mjs",
    ],
    outputs = [
        "web/browser/package-lock.json",
    ],
}

# ---------------------------------------------------------------------------
# Browser runtime
# ---------------------------------------------------------------------------

# Materialize the exact dependency tree from package-lock.json and copy only
# the files actually required by the browser into _build/browser-vendor.
browser-vendor = {
    cmd = "node tools/browser_vendor.mjs sync",
    inputs = [
        "web/browser/package.json",
        "web/browser/package-lock.json",
        "tools/browser_vendor.mjs",
    ],
    outputs = [
        "_build/browser-vendor/**",
    ],
}

# Explicit dependency update.
browser-vendor-update = {
    cmd = "node tools/browser_vendor.mjs update",
    inputs = [
        "web/browser/package.json",
        "web/browser/package-lock.json",
        "tools/browser_vendor.mjs",
    ],
    outputs = [
        "web/browser/package-lock.json",
        "_build/browser-vendor/**",
    ],
}

browser-vendor-clean = {
    cmd = "node tools/browser_vendor.mjs clean",
}

# ---------------------------------------------------------------------------
# Development environment
# ---------------------------------------------------------------------------

# Run this after a fresh checkout, after `pixi install`.
dev-setup = {
    depends-on = [
        "browser-vendor",
    ],
}

# Your existing application task should depend on the browser runtime.
dev = {
    cmd = "python src/tcm/main.py",
    depends-on = [
        "browser-vendor",
    ],
}

# ---------------------------------------------------------------------------
# PyInstaller
# ---------------------------------------------------------------------------

build-exe = {
    cmd = "pyinstaller tcm.spec",
    depends-on = [
        "browser-vendor",
    ],
}
```

Pixi's task model explicitly supports `depends-on`, and its task cache fingerprints the declared inputs/outputs and command, so this is a natural dependency edge rather than custom shell logic. ([Pixi][5])

I would keep `nodejs` in the normal development environment because the **environment itself now contains the tooling required to reconstruct the browser runtime**. The browser runtime is still not a Python dependency; Node is simply the build/install tool.

## 7. Browser server resource mapping

Your existing Python `server.py` should expose two application-owned paths in addition to `/api/document` and `/api/asset`:

```text
/
    web/browser/src/index.html

/viewer.js
    web/browser/src/viewer.js

/viewer.css
    web/browser/src/viewer.css

/vendor/
    _build/browser-vendor/
```

The important security distinction is:

```text
/vendor/...       application-owned packaged runtime
/api/asset        explicitly allowed documentation assets
/api/document     explicitly allowed source/Markdown files
```

`/vendor/` must **never** be mapped to the user's `allowed_roots`; it comes from the application's own installation/package directory.

For example, the server handler can conceptually route:

```python
if path == "/":
    serve_static(APP_BROWSER_DIR / "index.html")

elif path == "/viewer.js":
    serve_static(APP_BROWSER_DIR / "viewer.js")

elif path == "/viewer.css":
    serve_static(APP_BROWSER_DIR / "viewer.css")

elif path.startswith("/vendor/"):
    serve_vendor(
        BROWSER_VENDOR_DIR,
        path.removeprefix("/vendor/"),
    )

elif path == "/api/document":
    ...

elif path == "/api/asset":
    ...
```

The existing allowed-root security check applies to `/api/document` and `/api/asset`, **not** to `/vendor/`.

## Development workflow

A fresh checkout is now deterministic:

```text
git clone ...
cd monorepo/tcm

pixi install
pixi run dev-setup
pixi run dev
```

`pixi install` creates the Python + Node development environment from `pixi.lock`. The `dev-setup` task then runs `browser-vendor`, which runs `npm ci` using the committed `web/browser/package-lock.json` and copies the required runtime files into `_build/browser-vendor/`.

After that:

```text
pixi run dev
```

does not need Internet access for the browser runtime.

The first documentation click simply starts your Python localhost server and opens the browser. Node/npm are not involved at runtime.

## Updating the browser runtime

This is deliberately a separate explicit operation:

```text
pixi run browser-vendor-update
```

Internally:

```text
npm install --save-exact marked@latest mathjax@latest highlight.js@latest
        ↓
package.json updated
        ↓
package-lock.json regenerated
        ↓
exact resolved + integrity values updated
        ↓
npm ci
        ↓
_build/browser-vendor rebuilt
```

So the Git diff is exactly what you want:

```text
web/browser/package.json
web/browser/package-lock.json
```

changed, while:

```text
web/browser/node_modules/
_build/browser-vendor/
```

remain untracked/generated.

If you want to update only one library, I would also expose:

```text
pixi run browser-update-marked
pixi run browser-update-mathjax
pixi run browser-update-highlight
```

with the Node script accepting a package argument; that is a small refinement, not a change to the architecture.

## Updating the Python environment

That remains completely independent:

```text
pixi update
```

updates Python/Conda dependencies and `pixi.lock`.

The two lock mechanisms now have clear responsibilities:

```text
pixi.lock
    Python / Conda / PyPI environment

web/browser/package-lock.json
    Node / browser runtime dependency tree
```

There is no artificial npm-to-Python dependency.

For reproducible CI/builds:

```text
pixi install --locked
pixi run build-exe
```

The `build-exe` dependency automatically materializes the browser runtime first. Pixi documents `--locked` as checking that the environment lockfile is current, while its task dependency system ensures prerequisite tasks execute before dependent tasks. ([Pixi][7])

## Why this is better than the previous `vendor.toml`

The previous design duplicated npm's package-management job in Python. This version has one authoritative resolver:

```text
                     npm registry
                          │
                          ▼
                   npm package metadata
                          │
                          ▼
                 package.json + npm
                          │
                          ▼
                    package-lock.json
                   version
                   resolved
                   integrity
                   dependencies
                          │
                          ▼
                       npm ci
                          │
                  exact node_modules
                          │
                          ▼
               Node sync script copies
             only runtime browser artifacts
                          │
                          ▼
                 _build/browser-vendor
```

That is the boundary I would keep. npm's lockfile is specifically designed to describe the exact dependency tree, including `resolved` and `integrity`; reinventing that format in TOML gains nothing. ([npm Docs][1])

The resulting repository has a clean separation:

```text
src/.../browser/
    Python implementation

web/browser/src/
    first-party HTML/CSS/JavaScript

web/browser/package.json
    first-party declaration of browser dependencies

web/browser/package-lock.json
    exact browser dependency lock

tools/browser_vendor.mjs
    reproducible Node/Pixi integration

_build/browser-vendor/
    generated third-party browser runtime

docs/
    actual documentation
```

That is the setup I would use for this subproject. It also handles the MathJax-specific issue correctly: the complete npm package is available to the local server, so `.js`, font/data files and dynamically requested MathJax resources remain available rather than being guessed or selectively copied.
