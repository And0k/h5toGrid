# Справочник по полям схемы конфигурации и метаданным устройств

Каждый YAML-файл запуска (`cfg_proc/run/{source_stem}.yaml`) представляет собой структурированную конфигурацию Hydra/OmegaConf.

Все поля определены в `tcm/schema.py` через класс данных `Config` и зарегистрированные группы
(`input`, `out`, `filter`, `program`).

Каждый YAML-файл запуска начинается с ``# @package _global_``, поэтому Hydra объединяет его с конфигурацией верхнего уровня.


> **Настройки поведения** (остановки по фазам, режимы коррекции времени, порядок столбцов,
> `overwrite_db`, калибровка азимута, примеры YAML) — в [настройке поведения](config_tuning.md).
> Внутреннее устройство — в [устройстве CLI](../project_developer_guide/CLI.md).

## `input` — Источник данных и параметры

| Поле = По умолчанию | Назначение |
|---------------------|------------|
| `path` = — | Абсолютный путь к файлу данных. Определяет идентификатор зонда (pcid). |
| `tables` = `['incl*']` | Группы таблиц в бинарных (NC/HDF5) данных; допустимы glob-шаблоны (`incl*` — все инклинометры). Для текстовых данных выводится из имени файла. |
| `ids` = `None` | Обработать только указанные ID зондов (напр. `[i01, i_p02]`). Повторный запуск одного проблемного зонда без затрагивания остальных. |
| `prefix` = `'I*[_0]'` | Фильтр префикса имени файла при обнаружении файлов CSV. |
| `text_type` = `None` | Вариант раскладки столбцов (`i`, `p`, `b`, `d`, `w`). Определяется автоматически из заголовка файла; укажите здесь, если автоопределение не сработало. |
| `text_line_regex` = `None` | Пользовательское регулярное выражение для разбора строк необработанного текста. Требуется только при нестандартных форматах файлов, когда автоопределение не работает. |
| `coefs` = см. [§coefs](#inputcoefs--калибровочные-коэффициенты) | Калибровочные коэффициенты — основа точности измерений. Автозагрузка при первом запуске; исправьте здесь для точной настройки конкретного зонда. |
| `coefs_path` = `tcm/cfg/coef/calibration.h5` | Источник коэффициентов — каталог YAML-файлов по зондам либо один файл HDF5/NC/YAML; подробности в режимах dir/file ниже. |
| `date_to_from` = `None` | Два штампа времени `[реальное, сырое]` — их смещение становится `dt_from_utc`. |
| `dt_from_utc` = `0` | Смещение от UTC в секундах. Укажите часовой пояс для перевода времени прибора в UTC. |
| `min_date` = `None` | Краткая запись для `time_ranges` — объединяется автоматически. |
| `max_date` = `None` | Краткая запись для `time_ranges` — объединяется автоматически. |
| `time_ranges` = `None` | Временное окно обработки `[начало, конец, …]` в ISO формате. Заполняется автоматически из данных при первом запуске — сузьте для фокусировки на определённых периодах. |
| `min` = `{}` | Жёсткие нижние границы сырых значений датчиков. Строки вне границ **удаляются целиком**. `M` расширяется в `Mx`/`My`/`Mz`. |
| `max` = `{}` | Жёсткие верхние границы сырых значений датчиков. Такое же расширение `M`, как для `min`. |
| `corr_time_mode` = `True` | Обработка целочисленных меток времени: `True` = привязка к субсекундной сетке, `None` = только маскирование, `"delete_inversions"` = очистка с сохранением временных меток. |
| `corr_time_outlier_threshold_s` = `0.6` | Чувствительность обнаружения пиков (секунды). Чем ниже — тем строже. Отсчёты, отклоняющиеся от соседей более чем на это значение, помечаются. |
| `dt_interp_between` = `1.5` | Минимальный промежуток (секунды) для отличия реального провала данных от дрожания в пределах пачки. |
| `max_incl_of_fit_deg` = `None` | Экстремальный угол наклона°, после которого кривая скорости заменяется линейной касательной в точке Θ_last. Переопределяет последний элемент `kVabs` — см. [§Вычисление скорости](../methodology/velocity_Ru.md). |
| `calc_version` = `'trigonometric(incl)'` | Метод расчёта скорости. `trigonometric(incl)` (формулы (1)–(3)) стандартный; прочие варианты экспериментальны — см. [§Вычисление скорости](../methodology/velocity_Ru.md). |
| `dt_hole_warning` = `600` | Порог предупреждения о провалах данных (секунды). Промежутки больше этого вызывают предупреждение. `None` отключает. |
| `fs_rounding` = `100` | Округление оценённой частоты дискретизации до ближайшего кратного этому значению. 0 = точная оценка. |
| `tables_log` = `['{}/logFiles']` | Шаблон имени группы лога NC (`{}` → имя таблицы). |

Единственное обязательное поле — `coefs`; остальные замещаются значениями
по умолчанию. Типы полей — [датакласс `ConfigIn_InclProc`](../../src/tcm/schema.py)
(этап загрузки + калибровка: `ConfigInCalib_InclProc`).

### `input.path` <mode>probe</mode>

Абсолютный путь к файлу данных. Имя файла **определяет идентификатор зонда** (pcid):
пайплайн извлекает ведущую букву типа (`i` — инклинометр, `w` — волновой датчик),
необязательную букву модели (`p`, `b`, `d`) и номер зонда — напр. `i_01.txt` → pcid
`i01`, `i_p05_data.txt` → pcid `i_p05`. Неверное имя файла приводит к неверной таблице
и неверным коэффициентам.

### `input.path` <mode>search</mode>

Поиск поддерживает glob (`*i*.txt`), regex (`i.*\.txt`) или директорию. Если указан
суффикс `.yaml`, то ищутся не данные, а существующие конфигурации.

#### Detailed

Путь поиска данных должен быть абсолютным путем к:
- **директории** (напр. `B:\Cruises\BalticSea\inclinometer\260624@ip05-Press\_raw`)
- к сырому файлу или файлам используя **glob** (`*i*.txt`) / **regex** (`i.*\.txt`) — для фильтрации файлов по имени
- к конфигурации/ям (обязательно закончить на **`.yaml`**) — загрузка готовых конфигураций напрямую из подпапки `cfg_proc/run/`

Ожидаемая структура для входных данных ([подробнее](io_formats.md#directory-layout))
```text
├── _raw\            ← сырые данные (.txt/.csv/.h5/.nc) — ОБЯЗАТЕЛЬНО
├── cfg_proc\
│   └── run\         ← YAML-конфиги зондов (автогенерация при первом сканировании)
```


### `input.coefs_path` <mode>dir</mode>
Каталог с YAML-файлами коэффициентов — программа читает `{tbl}.yaml`
(напр. `incl_p05.yaml`) со структурой `input.coefs`. Если файла зонда в каталоге
нет, берётся следующий источник цепочки [приоритетов](io_formats.md#coefficient-source-priority)
(встроенный `yaml_export/`, затем значения по умолчанию); уже заданные в конфиге
зонда коэффициенты имеют приоритет над каталогом.

### `input.coefs_path` <mode>file</mode>
Единый исходный файл коэффициентов: HDF5 (`.h5`), NetCDF4 (`.nc`) или
экспортированный YAML (`.yaml`). YAML задаёт одни и те же коэффициенты для всех зондов,
HDF5/NetCDF — выбираются из групп, соответствующих идентификатору зонда
(аналогично наименованию таблиц сырых данных). Допускаются пути, разделённые запятыми
(цепочка резервных вариантов, побеждает первое наличие/совпадение).

### `input.time_ranges`
Временное окно обработки — ограничивает обработку данными в нём; при первом
запуске заполняется автоматически из крайних строк данных.

#### Detailed
Двухэлементный список `[начало, конец]` в формате ISO (`"YYYY-MM-DDTHH:MM:SS"`).
Допустимы несколько пар (`[н1, к1, н2, к2, ...]`) для непересекающихся интервалов.

**Взаимодействие с `overwrite_db`**: когда `overwrite_db=None` и `time_ranges` —
подмножество существующих данных NC, конвейер проверяет сохранённые параметры
`/param_spans/{tbl}` — если они изменились, возникает `ValueError` с унифицированным
diff. Передайте `out.overwrite_db=splice` для принудительной повторной обработки.
Когда `time_ranges` расширяется за пределы существующих данных, добавляется только новый хвост.

**Наведение в GUI** (сравнение вживую с `info_devices`): _совпадает_ (`kept`) при равенстве, _шире_ (`broader`) при выходе за любой край (предупреждающая подсветка), _отличается_ (`differs`) при сужении или смещении — текст строки состояния пересчитывается при каждом наведении/правке, никогда не кэшируется со сканирования. См. [Архитектура GUI](../project_developer_guide/GUI_architecture.md#coef_sheetpy--composition-root--treeeditrow-space-core).

**Семантика конечной границы**: конечные значения **включительны** в конфигурации.
Внутри конвейера они преобразуются в исключительные (целые секунды получают +1 с),
чтобы предотвратить потерю данных на границе из-за дрейфа точности CF float64.

### `input.min` {#input-min-max}
Жёсткая нижняя граница сырых значений датчиков — этап загрузки **DROP**: строки
вне границы удаляются целиком. В отличие от `filter.min`/`filter.max` — этап
обработки NaN-out, строки сохраняются.

#### Detailed
`M` — сокращение для `Mx`, `My`, `Mz`. Если `M` задан, а отдельные оси нет, значение
копируется на все три:

```yaml
input:
  max: {M: 500}           # → Mx=500, My=500, Mz=500
  max: {Mx: 500, My: 400} # явная перезапись M для Mx, My; Mz=500 из M
```

Сокращение `M` разворачивается автоматически на этапе композиции конфигурации.

### `input.max`
Верхнее зеркало `min` — такой же этап загрузки **DROP** и расширение `M`.

## `input.calib` — Корректировка калибровки на этапе обработки

Применяются на этапе обработки, после загрузки, в :func:`tcm._xr.coefs.prepare_coefs`.
Типы полей — [датакласс `ConfigInCalib_InclProc`](../../src/tcm/schema.py).

| Поле = По умолчанию | Физический смысл |
|---------------------|------------------|
| `g0xyz` = `None` | Пользовательский вектор эталона гравитации. При задании перекрывает `Rz` вычисленной ротацией. |
| `time_ranges_zeroing` = `[]` | Интервалы, когда прибор висел ровно. Пайплайн вычисляет ротацию для совмещения оси Z датчика с гравитацией (`Rz`). |
| `time_ranges_azimuth` = `[]` | Интервалы, когда прибор был наклонён в известном направлении. Пайплайн калибрует сдвиг азимута (`azimuth_shift_deg`) по единичным векторам магнитометра и акселерометра. |
| `coordinates` = `None` | Координаты станции `[широта, долгота]` — включает коррекцию магнитного склонения (направления скорости по истинному северу). |
| `azimuth_add` = `0` | Ручная подстройка азимута°, добавляется к калиброванному по данным сдвигу. |

### `input.calib.g0xyz`
Пользовательский вектор эталона гравитации.

#### Detailed
Сырой вектор акселерометра `[Ax, Ay, Az]`, измеренный при известном нулевом
наклоне. При задании **перекрывает** любой существующий `Rz` — вычисляет
ротацию для совмещения Z датчика с гравитацией напрямую, минуя
`time_ranges_zeroing`.

### `input.calib.time_ranges_zeroing`
Интервалы, когда прибор висел ровно — пайплайн вычисляет ротацию `Rz`,
совмещающую ось Z датчика с гравитацией; записывается в YAML зонда.

#### Detailed
Прибор висит по отвесу. Пайплайн усредняет данные акселерометра за окно и
вычисляет матрицу вращения `Rz`. Альтернатива:
[`input.calib.g0xyz`](#inputcalibg0xyz) (сырой вектор акселерометра при
известном нулевом наклоне) перекрывает любой `Rz`, вычисленный по данным.

### `input.calib.time_ranges_azimuth`
Интервалы, когда прибор был наклонён в **известном направлении** — пайплайн
вычисляет `azimuth_shift_deg` по калиброванным единичным векторам магнитометра
и акселерометра; записывается в YAML зонда.

#### Detailed
Вычисление азимута использует только калиброванные единичные векторы (без
расчёта скорости/модуля), поэтому не зависит от `kVabs` или коэффициентов
наклон–модуль.

### `input.calib.coordinates`
Координаты станции `[широта, долгота]` в десятичных градусах — включает
коррекцию магнитного склонения, переводя направления скорости с магнитного
на истинный север. Склонение вычисляется на текущую дату для точки станции.

#### Detailed
Применяется поверх вычисленного по данных сдвига азимута вместе с
`input.calib.azimuth_add` — порядок слоёв см.
[`input.coefs.azimuth_shift_deg`](#inputcoefsazimuth_shift_deg).

### `input.calib.azimuth_add`
Ручная подстройка азимута°, добавляется к калиброванному по данным сдвигу.

#### Detailed
Слои: `azimuth_add` (ручное смещение, градусы) и `coordinates` (магнитное
склонение через `pygeomag`) применяются **после** вычисленного по данным
сдвига азимута, перед разрешением направления скорости — см.
[`input.coefs.azimuth_shift_deg`](#inputcoefsazimuth_shift_deg).

```yaml
input:
  calib:
    time_ranges_zeroing: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]
    time_ranges_azimuth: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]
    coordinates: [54.70, 20.51]   # Калининград
    azimuth_add: 2.5              # ручная подстройка
```

## `input.coefs` — Калибровочные коэффициенты
Загружается из файла коэффициентов и копируется в каждый YAML-файл для каждого зонда при первом запуске.
Редактируйте их, чтобы обновить калибровку зонда — изменения сохраняются автоматически.


| Поле = По умолчанию | Физический смысл |
|---------------------|------------------|
| `Ag` = `[[1.73e-3,0,0],[0,1.73e-3,0],[0,0,1.73e-3]]` | Матрица масштаба акселерометра: `G = Ag · (Axyz − Cg)` |
| `Cg` = `[10, 10, 10]` | Вектор смещения акселерометра |
| `Ah` = Единичная | Матрица масштаба магнитометра: `H = Ah · (Mxyz − Ch)` |
| `Ch` = `[10, 10, 10]` | Вектор смещения магнитометра |
| `Rz` = Единичная | Ротация совмещения датчика и прибора, применяемая после калибровки |
| `kVabs` = `[10, −10, −10, −3, 3, 70]` | Полином скорости `Vabs(наклон)`, формула (3) — см. [§Вычисление скорости](../methodology/velocity_Ru.md) |
| `P_t` = `None` | Полином давление–температура 2D для зондов типа `p`; при задании заменяет `P`/`PBattery`/`PTemp`. |
| `P` = `[0, 1]` | Линейная коррекция вспомогательного датчика №1: `y = P[0] + P[1]·x` |
| `PBattery` = `[0, 1]` | Линейная коррекция напряжения батареи |
| `PTemp` = `[0, 1]` | Линейная коррекция температуры |
| `azimuth_shift_deg` = `180` | Поправка азимута° — переводит направление наклона из датчика в географические координаты; компенсирует инверсию знака магнитометра при загрузке. См. [Калибровка азимута](config_tuning.md#azimuth-calibration). |
| `dates` = `{}` | Даты калибровки по компонентам |
| `date` = `None` | Общая дата калибровки |

Типы и размерности полей — [датакласс `ConfigInCoefs_InclProc`](../../src/tcm/schema.py).
Приоритет разрешения (свой конфиг → файл `coefs_path` → встроенный `yaml_export/` →
значения по умолчанию): см.
[§Приоритет источников коэффициентов](io_formats.md#coefficient-source-priority).

### `input.coefs.azimuth_shift_deg`
Поправка азимута° — переводит направление наклона из датчика в географические координаты.

#### Detailed
**Калибровка азимута**: `time_ranges_azimuth` задаёт интервал, когда прибор был
наклонён в **известном направлении** (напр. известное направление наклона на
север). Пайплайн вычисляет сдвиг азимута из калиброванных единичных векторов
магнитометра и акселерометра и записывает `azimuth_shift_deg` в YAML зонда.

**Слои**: `azimuth_add` (ручное смещение, градусы) и `coordinates`
(магнитное склонение, текущая дата) применяются **поверх**
вычисленного по данным азимута.

### `input.coefs.P_t`
Полином давление–температура: преобразует сырые отсчёты давления и температуру
в физическое давление.

#### Detailed
Двумерный полином `polyval2d(u, t, P_t)` по сырым отсчётам давления `u`
(`P`/`P_counts`) и температуре `t` (`Temp`); элемент `P_t[i][j]` — коэффициент
при `u^i·t^j` (шесть коэффициентов суммарной степени ≤ 2). Расчётное давление —
как откалибровано: относительно стандартного атмосферного давления P0 =
10.1325 дБар. Формула и происхождение коэффициентов:
[§Вычисление давления](../methodology/pressure_Ru.md).

## `out` — Выходная конфигурация

| Поле = По умолчанию | Назначение |
|---------------------|------------|
| `db_path` = `None` | Объединенный вывод нескольких зондов (`.proc.nc`) — все зонды объединены вдоль измерения `probe`. |
| `avg_db_path` = `None` | Вывод по каждому зонду в виде бинов (`.proc_Avg.nc`) — одна группа на зонд на размер бина. |
| `not_joined_db_path` = `None` | Вывод с полным разрешением по каждому зонду (`.proc_noAvg.nc`) — каждый образец сохранен. |
| `raw_db_path` = `None` | Архив необработанных данных (`.raw.nc`) — необработанные показания + калибровочные коэффициенты для последующей обработки. |
| `table` = `''` | Переопределить имя выходной таблицы. Если не пусто, заменяет автоматически вычисленный pcid на суффиксы текстовых файлов и имена групп HDF5. |
| `tables_log` = `['{}/logFiles']` | Шаблон(ы) имени группы лога NC при сохранении (`{}` → имя таблицы). |
| `b_incremental_update` = `True` | Режим инкрементального дописывания HDF5-конвейера — в NC-конвейере заменён логикой `overwrite_db`. |
| `b_overwrite` = `False` | Флаг перезаписи HDF5-конвейера — заменён на `overwrite_db`, в NC-конвейере не используется. |
| `dt_bins` = `[0, 2, 600, 3600, 7200]` | Усредняющие интервалы по времени (секунды). `0` = полное разрешение. Несколько значений дают отдельные выходные данные (например, `[0, 600, 3600]` = полное + 10 мин + 1 ч). |
| `dt_bins_min_save_text` = `1` | Минимальный размер интервала (секунды) для экспорта в TSV. Bin=0 пропускается, если >0. Установите значение 0, чтобы включить данные с полным разрешением в текстовый вывод. |
| `split_period` = `''` | Разделить вывод на временные блоки (например, `'1D'` = ежедневные файлы). Пусто = один непрерывный вывод. |
| `text_path` = `'text_output'` | Каталог для выходных файлов TSV. Создается автоматически, если отсутствует. |
| `text_date_format` = `'%Y-%m-%d %H:%M:%S.%f'` | Строка формата даты для временных меток TSV. |
| `text_columns` = `[]` | Фильтровать столбцы, которые отображаются в выводе TSV. Пусто = все доступные. Столбцы, перечисленные, но отсутствующие в конкретном выводе, молча пропускаются. |
| `b_all_to_one_col` = `False` | Многозондовая компоновка: `False` = чередование столбцов (`v_i01, u_i01, …`), `True` = укладка строк. |
| `b_overwrite_text` = `True` | Перезапись существующих TSV-файлов. Установите `False`, чтобы сохранить предыдущие экспорты. |
| `b_split_by_time_ranges` = `False` | Разделение вывода по границам `time_ranges` — каждый интервал получает свой собственный файл. |
| `b_del_temp_db` = `False` | Удаление временных файлов HDF5 после обработки. |
| `overwrite_db` = `None` | Стратегия перезаписи NC. `None` = только добавление (безопасно). `"splice"` = замена перекрывающихся данных, сохранение остальных. `"trim"` = удаление за пределами `time_ranges`. `"export"` = только TSV, запись в NC запрещена. См. [§overwrite_db](#outoverwrite_db). |

Обязательные — только `dt_bins` и `text_path`. Типы полей —
[датакласс `ConfigOut_InclProc`](../../src/tcm/schema.py).

### `out.overwrite_db`

Управляет поведением конвейера при повторной обработке существующих выходных данных.

| `overwrite_db` | Параметры изменены? | `time_ranges` vs существующие | Поведение |
|:---:|:---:|:---:|---|
| `None` | Нет | подмножество | **Пропуск NC** — экспорт только TSV |
| `None` | Нет | расширяет | **Добавление** — только новый хвост |
| `None` | Да | расширяет | **Добавление + предупреждение** — существующие сохранены, новые добавлены |
| `None` | Да | содержится | **Ошибка** — предложить `out.overwrite_db=splice` |
| `"splice"` | — | подмножество | **Замена** — сохранение вне, замена внутри повторно обработанными |
| `"splice"` | — | расширяет | **Замена** — сохранение вне, замена/добавление внутри |
| `"splice"` | — | None | **Замена** — повторная обработка всех из источника |
| `"trim"` | — | подмножество | **Обрезка** — удаление вне `time_ranges`, без повторной обработки |
| `"trim"` | — | расширяет | **Обрезка + добавление** — обрезка существующих, обработка/добавление новых |
| `"export"` | — | любые | **Только экспорт** — блокировка записи NC, экспорт TSV |

Когда параметры обработки изменились и `overwrite_db=None`, конвейер сравнивает
сохранённую таблицу интервалов `/param_spans/{tbl}` с текущими значениями и выдаёт
`ValueError` с унифицированным diff. См.
[§повторный запуск](config_tuning.md#re-run-behavior) для полного контракта, включая позиции
инкрементального добавления и дедупликацию по логу.


## `filter` — Пороги контроля качества на этапе обработки

`filter` — это **этап обработки**: значения, превышающие пороговые значения, становятся NaN (строки
**сохраняются**, а не удаляются). В отличие от `input.min`/`max` — **этап загрузки DROP**,
который удаляет целые строки. Одни и те же имена ключей могут встречаться в обоих пространствах имен с
разной семантикой.

| Поле = По умолчанию | Назначение |
|---------------------|------------|
| `min` = `{}` | Нижние границы: значения с `\|col\| < min[col]` установлены в NaN. |
| `bad_p_at_bursts_starts_period` = `''` | Период очистки импульсов давления (например, `'1h'`). Обнуляет первые 2 выборки за импульс для удаления артефактов запуска. Пустота отключает. |
| `max` = `{'g_minus_1': 1, 'h_minus_1': 8}` | Верхние границы. `M` разворачивается в `Mx`/`My`/`Mz`. |

Типы полей — [датакласс `ConfigFilter_InclProc`](../../src/tcm/schema.py).

### `filter.max`
Верхние границы вычисляемых на этапе обработки столбцов — значения выше
порога становятся NaN (строки сохраняются).

#### Detailed
Ключи порогов адресуют вычисляемые на этапе обработки столбцы:
`g_minus_1 = ∥Gxyz∥ − 1` (отклонение модуля гравитации),
`h_minus_1 = ∥Hxyz∥ − 1` (отклонение модуля магнитного поля);
`M` разворачивается в `Mx`/`My`/`Mz` так же, как в `input.min`/`max`.

### Calibration filter extensions (`filter/calib`)

Когда точка входа калибровки использует `filter: calib`, группа фильтров добавляет
типизированные переопределения подавления импульсов:

| Поле | Тип | Назначение |
|-------|------|---------|
| `blocks` | `List[int]` | Размеры блоков подавления импульсов Apex (по умолчанию `[21, 7]`) |
| `offsets` | `List[float]` | Пороговые значения смещения подавления импульсов Apex |
| `std_smooth_sigma` | `float` | Сигма сглаживания подавления импульсов Apex |
| `A` | `ConfigFilterChannel` | Переопределения по осям для акселерометра |
| `M` | `ConfigFilterChannel` | Переопределения по осям для магнитометра |
| `no_works_noise` | `Dict[str, float]` | Порог шума на канал |


## `proc` — Параметры обработки по точке входа (опционально)
`proc` — это **необязательная** группа для каждой точки входа. Для точки входа обработки групп нет.

| Точка входа | Опция `proc` | Класс данных | Назначение |
|-------------|--------------|-----------|---------|
| Обработка | *(none)* | — | Все параметры обработки находятся в `out.dt_bins` + `input.calc_version` |
| Калибровка | `calib` | `ConfigProcCalib` | Сопоставляется с полями `PipelineConfig` |
| Спектр | `spectrum` | `ConfigProcSpectrum` | **Зарезервировано** — модуль spectrum еще не портирован |
