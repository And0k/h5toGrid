# Справочник по полям схемы конфигурации и метаданным устройств

## Ключи командной строки не включенные в типизировнную конфигурацию (не в YAML)

| Поле | Назначение |
|------|------------|
| `path_field` = — | Путь поиска данных/конфигураций[↓](#path_field) |
| `+input.min_date` = `None` | Начало интервала обработки (альтрнатива начала `input.time_ranges`, объединится с ним, если оно тоже задано) |
| `+input.max_date` = `None` | Конец интервала обработки (альтрнатива конца интервала из `time_ranges`, объединится с ним, если оно тоже задано) |

`path_field` - Обязательный первый аргумент CLI (опциональный для запуска GUI, где задается полем поиска данных).

### `path_field`

Путь поиска исходных данных / конфигураций их обработки.

#### Detailed
Конфигурации обработки будут созданы, если их нет, в подкаталоге `cfg_proc/run/`.
Выходные файлы будут в каталоге выше (если в пути подкаталог `_raw`, то выше него).

##### Important

Введите aбсолютный путь к:
- **каталогу** поиска данных с маской (glob) `*i*.txt`, или
- сырому файлу или файлам через **glob** (`*i*.txt`) / **regex** (`i.*\.txt`) имени файлов, или
- имеющимся конфигурации/ям (если закончить на **`.yaml`**) из подпапки сырых файлов `cfg_proc/run/`

Ожидаемая [структура для входных данных](io_formats.md#directory-layout):
```text
├── _raw\            ← сырые данные (`.txt`/`.csv`/`.h5`/`.nc`) — ОБЯЗАТЕЛЬНО
├── cfg_proc\
│   └── run\         ← YAML-конфиги зондов (автогенерация при первом сканировании)
```

## Поля конфигурации YAML-файлов и командной строки (типизированная конфигурация с помощью библиотеки Hydra/OmegaConf)

YAML файлы конфигурации хранятся в `cfg_proc/run/{yymmdd_hhmm}@pcid[-comment].yaml` в каталоге сырых данных, где
- `yymmdd_hhmm` — метка времени из `input.time_ranges[0]` или из первой строки исходных файлов (отсутствует, если нет найдена);
- pcid — стандартизованный идентификатор, например, `i3.txt` → `i03`;
- `-comment` — часть имени исходного файла после pcid (регистр и разделители `-`/`_` нормализуются:
  `INKL_P05_маг.TXT` → `-маг`) — файлы одного зонда получают различные имена без коллизий.

Устаревшие конфиги (`input.path` указывает на несуществующий файл) **никогда не удаляются** —
регенерация перезаписывает только файл с тем же именем; копии (пробел в имени YAML) и YAML
с несовпадающей идентичностью остаются на диске с предупреждением и без обработки. Полные правила:
[Соответствие конфиг-файл](io_formats.md#config-file-matching)
(pcid + comment через `format.pcid_key`).

Все поля определены в `tcm/schema.py` через класс данных `Config` и зарегистрированные группы
(`input`, `out`, `filter`, `program`).

Каждая YAML-конфигурация запуска начинается с `# @package _global_`, поэтому Hydra объединяет его с конфигурацией верхнего уровня.


## `input` — Источник данных и параметры его начальной обработки

| Поле = По умолчанию | Назначение |
|---------------------|------------|
| `path` = — | Абсолютный путь к файлу данных. Определяет идентификатор зонда (pcid)[↓](#inputpath) |
| `tables` = `['incl*']` | Группы таблиц в бинарных (NC/HDF5) данных; допустимы glob-шаблоны (`incl*` — все инклинометры). Для текстовых данных выводится из имени файла. |
| `ids` = `None` | Обработать только указанные ID зондов (напр. `[i01, i_p02]`). Повторный запуск одного проблемного зонда без затрагивания остальных. |
| `prefix` = `'I*[_0]'` | Фильтр префикса имени файла при обнаружении файлов CSV. |
| `text_type` = `None` | Вариант раскладки столбцов (`i`, `p`, `b`, `d`, `w`). Определяется автоматически из заголовка файла; укажите здесь, если автоопределение не сработало. |
| `text_line_regex` = `None` | Пользовательское регулярное выражение для разбора строк необработанного текста. Требуется только при нестандартных форматах файлов, когда автоопределение не работает. |
| `coefs` = см. [§coefs](#inputcoefs--калибровочные-коэффициенты) | Калибровочные коэффициенты. Загружаются из файла калибровки при первом запуске под конкретный зонд. |
| `date_to_from` = `None` | Две метки одного момента — [истинная, показания прибора]: разница даст поправку часов `dt_from_utc`. Заполняйте, когда время прибора сбито. |
| `dt_from_utc` = `0` | Смещение от UTC в секундах. Укажите часовой пояс для перевода времени прибора в UTC. |
| `time_ranges` = `None` | Временное окно обработки[^](#inputtime_ranges) `[начало, конец, …]` |
| `min` = `{}` | Жёсткие нижние границы сырых значений датчиков. Строки вне границ **удаляются целиком**. `M` расширяется в `Mx`/`My`/`Mz`[↓](#input-min-max) |
| `max` = `{}` | Жёсткие верхние границы сырых значений датчиков. Такое же расширение `M`, как для `min`[↓](#inputmax) |
| `corr_time_mode` = `True` | Обработка целочисленных меток времени: `True` = привязка к субсекундной сетке, `None` = только маскирование, `"delete_inversions"` = очистка с сохранением временных меток. |
| `corr_time_outlier_threshold_s` = `0.6` | Чувствительность обнаружения пиков (секунды). Чем ниже — тем строже. Отсчёты, отклоняющиеся от соседей более чем на это значение, помечаются. |
| `dt_interp_between` = `1.5` | Минимальный промежуток (секунды) для отличия реального провала данных от дрожания в пределах пачки. |
| `dt_hole_warning` = `600` | Порог предупреждения о провалах данных (секунды). Промежутки больше этого вызывают предупреждение. `None` отключает. |
| `fs_rounding` = `100` | Округление оценённой частоты дискретизации до ближайшего кратного этому значению. 0 = точная оценка. |
| `tables_log` = `['{}/logFiles']` | Шаблон имени группы лога NC (`{}` → имя таблицы). |

Единственное обязательное поле — `coefs`; остальные замещаются значениями
по умолчанию. Типы полей — [датакласс `ConfigIn_InclProc`](../../src/tcm/schema.py)
(этап загрузки + калибровка: `ConfigInCalib_InclProc`).

### `input.path`

Абсолютный путь к файлу данных. Имя файла должно соответствовать **идентификатору зонда** (pcid), определяет имена конфигураций.

#### Detailed
Изначально называйте файлы правильно: **идентификатор зонда** (pcid) определяет используемые коэффициенты и суффиксы выходных данных. Извлекается из начальной части имени файла с числом до символов "_" и "-", состоит из типа (`i` — инклинометр, `w` — волнограф), необязательной буквы модели (`p`, `b`, `d`) и номера зонда.
Генерируемые файлы с префиксом `@{pcid}` — копий строк из оригинальных файлов прошедших проверку формата, при обработке берутся автоматически вместо аналогичных без префикса. Пример: pcid(`INKL_P05_Press.TXT`)=pcid(`@i_p5`)=`i_p05`.

### `input.time_ranges`
Ограничте обработку временны́м окном. При первом запуске заполняется автоматически из крайних строк данных.

#### Detailed

Попарный список `[начало, конец]`: (`[н1, к1, н2, к2, ...]`) непересекающихся интервалов. Cузьте — для обработки части, укажите несколько — для пропусков между ними.

- Конец интервала обрабоатывается включительно. Если конец пары не указан - берется всё до конца.

- При работе с NetCDF, когда там уже есть данные (повторный запуск), будут дописаны только новые данные:
старые данные будут перезаписаны только если вы меняли коэффициенты или параметры и явно указали необходимость перезаписия с помощью `out.overwrite_db`, иначе программа остановится. [Повторный запуск](config_tuning.md#re-run-behavior).

### `input.min` {#input-min-max}
Жёсткая нижняя граница сырых значений датчиков — этап загрузки **DROP**: строки
вне границы удаляются целиком. Если нужно сохранять строки - используйте `filter.min`/`max`.

> Сокращение `M` для `Mx`, `My`, `Mz` разворачивается автоматически на этапе композиции конфигурации (может использоваться в командной строке или конфигурации yaml). Если также заданы отдельные оси, то они имеют приоритет:

```yaml
input:
  max: {M: 500}           # → Mx=500, My=500, Mz=500
  max: {Mx: 500, My: 400} # явная перезапись M для Mx, My; Mz=500 из M
```

### `input.max`
Аналогично зеркально `min` (такой же этап загрузки **DROP** и расширение `M`)


## `input.coefs` — Калибровочные коэффициенты
### Detailed
При генерации конфигурации копируются в нее из файла коэффициентов (источник записывается в `input.path`: по умолчанию - из каталога программы).
### Таблица. Параметры и метаданные коэффишциентов

| Поле = По умолчанию | Физический смысл |
|---------------------|------------------|
| `Ag` = `[[1.73e-3,0,0],[0,1.73e-3,0],[0,0,1.73e-3]]` | Матрица масштаба акселерометра: `G = Ag · (Axyz − Cg)` |
| `Cg` = `[10, 10, 10]` | Вектор смещения акселерометра |
| `Ah` = Единичная | Матрица масштаба магнитометра: `H = Ah · (Mxyz − Ch)` |
| `Ch` = `[10, 10, 10]` | Вектор смещения магнитометра |
| `Rz` = Единичная | [Матрица вращения](../methodology/velocity_Ru.md#выравнивание-по-вертикали-r_z) для совмещения оси Z датчика с вертикалью |
| `kVabs` = `[10, −10, −10, −3, 3]` | Коэффициенты тригонометрического ряда скорости `Vabs(наклон)`, формула (3) — см. [§Вычисление скорости](../methodology/velocity_Ru.md) |
| `P_t` = `None` | Полином давление–температура 2D для зондов типа `p`; при задании заменяет `P`/`PBattery`/`PTemp`[↓](#inputcoefsp_t) |
| `P` = `[0, 1]` | Линейная коррекция вспомогательного датчика №1: `y = P[0] + P[1]·x` |
| `PBattery` = `[0, 1]` | Линейная коррекция напряжения батареи |
| `PTemp` = `[0, 1]` | Линейная коррекция температуры |
| `azimuth_shift_deg` = `180` | [Поправка азимута](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift)°: добавится к результирующему направлению, и по нему пересчитвываются u и v [↓](#inputcoefsazimuth_shift_deg) |
| `dates` = `{}` | Даты калибровки по компонентам |
| `date` = `None` | Общая дата калибровки |
| `path` = `tcm/cfg/coef/calibration.h5` | Источник коэффициентов — каталог YAML-файлов по зондам либо один файл HDF5/NC/YAML[↓](#inputcoefs_path) |
| `kVabs_switch_to_linear` = `70` | Экстремальный угол наклона° (Θ_last), после которого кривая скорости заменяется линейной касательной [§Вычисление скорости](../methodology/velocity_Ru.md). |
| `calc_version` = `'trigonometric(incl)'` | Метод расчёта скорости. `trigonometric(incl)` (формулы (1)–(3)) стандартный; прочие варианты экспериментальны — см. [§Вычисление скорости](../methodology/velocity_Ru.md). |




Типы и размерности полей — [датакласс `ConfigInCoefs_InclProc`](../../src/tcm/schema.py).
Приоритет разрешения (свой конфиг > файл `input.coefs.path` > встроенный `yaml_export/` >
значения по умолчанию): см.
[§Приоритет источников коэффициентов](io_formats.md#coefficient-source-priority).

### `input.coefs.azimuth_shift_deg`

#### Detailed
Поправку азимута также можно переопределить на основе данных наклона в известном направлении во время `input.calib.time_ranges_azimuth` — см [the configuration guide](../user_guide/configuration.md)
По умолчанию близка к 180° для компенсации инверсии знака магнитометра (мы выполням ее всегда)

### `input.coefs.P_t`
Полином давление–температура: преобразует сырые отсчёты давления и температуру
в физическое давление.

#### Detailed
Двумерный полином `polyval2d(u, t, P_t)` по сырым отсчётам давления `u`
(`P`/`P_counts`) и температуре `t` (`Temp`); элемент `P_t[i][j]` — коэффициент
при `u^i·t^j` (шесть коэффициентов суммарной степени ≤ 2). Расчётное давление —
как откалибровано: относительно стандартного атмосферного давления P0 =
10.1325 дБар. Формула и происхождение коэффициентов:
[§Вычисление давления](../methodology/pressure_Ru.md).
### `input.coefs.path` {#inputcoefs_path}
Источник коэффициентов — каталог YAML-файлов по зондам либо один файл YAML. Либо NetCDF/HDF5: выбираются группа {g}, соответствующая зонду.

#### Detailed

Путь к файлу конфигурации (`input.coefs.path`). Должен содержать коэффициенты `input.coefs`. Можно указать:

- единый исходный файл коэффициентов: HDF5 (`.h5`), NetCDF4 (`.nc`) или конфигурация с коэффициентами YAML (`.yaml`).
- каталог YAML-файлов по зондам должен содержать файлы `{g}.yaml`, где {g} — идентификатор зонда (`incl_{модель№}`)
- отсутствующий/неверный путь — допустим, если вручную уже указаны все необходимые параметры (имеют приоритет над данными из файла), еще будет попытка найти нужные коэффициенты из поставки `yaml_export/`: [цепочка приоритетов](io_formats.md#coefficient-source-priority).


## `input.calib`

Подкалибровка: обновляет текущие коэффициенты `input.coef`, после чего значения `calib` стираются.

### Detailed
Корректировка калибровки на этапе обработки, в т.ч. на основе данных или, если не требуется их загурзка 
(для `g0xyz`, `coordinates`, `azimuth_add`), можно до нее — в GUI: применить переключателями справа от значений.
В результате применения также удаляются значения `input.calib` и дата изменённых коэффициентов `input.coefs` заменится на текущую.

### Таблица: способы подкалибровки

| Поле = По умолчанию | Описание |
|---------------------|------------------|
| `g0xyz` = `None` | Вектор акселерометра `[Ax, Ay, Az]`, когда прибор висел вертикально[↓](#inputcalibg0xyz). Укажите для пересчета и замены `Rz` |
| `time_ranges_zeroing` = `[]` | Интервалы, когда прибор висел вертикально. Обновляет коэффициент [`Rz`](../methodology/velocity_Ru.md#выравнивание-по-вертикали-r_z), совмещая ось Z датчика с вертикалью [↓](#inputcalibtime_ranges_zeroing) |
| `time_ranges_azimuth` = `[]` | Интервалы, когда прибор был наклонён в известном направлении. Пайплайн калибрует сдвиг азимута ([azimuth_shift_deg](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift)) по единичным векторам магнитометра и акселерометра[↓](#inputcalibtime_ranges_azimuth) |
| `coordinates` = `None` | Координаты станции `[широта, долгота]` — включает коррекцию магнитного склонения (направления скорости по истинному северу)[↓](#inputcalibcoordinates) |
| `azimuth_add` = `0` | Добавить к **смещению азимута** (коэффициенту калибровки [azimuth_shift_deg](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift), °) [↓](#inputcalibazimuth_add) |
### Пример конфигурации

```yaml
input:
  calib:
    time_ranges_zeroing: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]
    time_ranges_azimuth: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]
    coordinates: [54.70, 20.51]   # Калининград
    azimuth_add: 2.5              # ручная подстройка
```

Типы полей — [датакласс `ConfigInCalib_InclProc`](../../src/tcm/schema.py).
Применение :func:`tcm._xr.coefs.prepare_coefs`.

### `input.calib.g0xyz`


#### Detailed
Вектор акселерометра `[Ax, Ay, Az]` (сырой или нормированный). Укажите для пересчета и замены [Rz](../methodology/velocity_Ru.md#выравнивание-по-вертикали-r_z), которая заменит коэффициент (`input.coefs.Rz`). Если задан, то `time_ranges_zeroing` будет игнорировано.

### `input.calib.time_ranges_zeroing`

#### Detailed
Укажите интервал(ы) когда прибор вертикален. Усредненный по ним вектор акселерометра (альтернатива
[`input.calib.g0xyz`](#inputcalibg0xyz)) будет использован для вычисления матрицы вращения `Rz`, которая будет использована для вычислений вместо текущей.

### `input.calib.time_ranges_azimuth`
Интервалы, когда прибор был наклонён в **известном направлении** — поправка будет
**добавлена** к коэффициенту [azimuth_shift_deg](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift), °

#### Detailed

`time_ranges_azimuth` задаёт интервал, когда прибор был **наклонён в известном направлении** 
(напр. известное направление наклона на север) для **Калибровки азимута**. [Сдвиг азимута \(\psi\)](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift) вычисляется по среднему направлению наклона по этим интервалам (со старым `azimuth_shift_deg`). Затем, добавив к нему `azimuth_add` (ручное смещение) и магнитное склонение (по `calib.coordinates`, если они указаны) обновляется коэффициент `azimuth_shift_deg` [Калибровка азимута](config_tuning.md#azimuth-calibration). 
Затем все данные указанных диапазонов input.time_ranges будут обрабоатываться с новым коэффициентом `azimuth_shift_deg`.


### `input.calib.coordinates`
Координаты станции `[широта, долгота]` в десятичных градусах — включает
коррекцию магнитного склонения, переводя направления скорости с магнитного
на истинный север.

#### Detailed
Магнитное склонение° вычисляется на текущую дату для точки станции 
(через [pygeomag](https://pygeomag.readthedocs.io/en/latest/)). Добавляется (вместе с `input.calib.azimuth_add`) к текущему коэффициенту [`input.coefs.azimuth_shift_deg`](#inputcoefsazimuth_shift_deg) (и обновляет текущую конфигурацию) перед обработкой данных.

### `input.calib.azimuth_add`

#### Detailed
`azimuth_add` - ручное смещение коэффициента калибровки°, добавится к коэффициенту калибровки [azimuth_shift_deg](../methodology/velocity_Ru.md#сдвиг-азимута-psi_shift) (вместе с  `input.calib.coordinates` — порядок см. в [`input.coefs.azimuth_shift_deg`](#inputcoefsazimuth_shift_deg)).

### `out.overwrite_db`

Управляет поведением конвейера при повторной обработке существующих выходных данных.

| `overwrite_db` | Параметры изменены? | `time_ranges` vs существующие | Поведение |
|:---:|:---:|:---:|---|
| `None` | Нет | подмножество | **Пропуск NC** — экспорт только TSV |
| `None` | Нет | расширяет | **Добавление** — только новый хвост |
| `None` | Да | расширяет | **Добавление + предупреждение** — существующие сохранены, новые добавлены |
| `None` | Да | содержится | **Ошибка** — предложить `out.overwrite_db=splice` |
| `"splice"` | — | подмножество | **Замена** — сохранение вне, замена внутри повторно обработанными |
| `"splice"` | — | расширяет | **Замена** — сохранение вне, замена/добавление внутри |
| `"splice"` | — | None | **Замена** — повторная обработка всех из источника |
| `"trim"` | — | подмножество | **Обрезка** — удаление вне `time_ranges`, без повторной обработки |
| `"trim"` | — | расширяет | **Обрезка + добавление** — обрезка существующих, обработка/добавление новых |
| `"export"` | — | любые | **Только экспорт** — блокировка записи NC, экспорт TSV |

Повторный запуск обсчета (с опцией записи/чтения NetCDF) при изменённых параметрах внутри записанного ранее в NetCDF временного окна данных возможен только через `"splice"`.
Полный контракт (позиции добавления, дедупликация по логу) см. в [повторный запуск](config_tuning.md#re-run-behavior).


## `filter` — Пороги контроля качества на этапе обработки

`filter` — это **этап обработки**: значения, превышающие пороговые значения, становятся NaN (строки
**сохраняются**, а не удаляются). В отличие от `input.min`/`max` — **этап загрузки DROP**,
который удаляет целые строки. Одни и те же имена ключей могут встречаться в обоих пространствах имен с
разной семантикой.

| Поле = По умолчанию | Назначение |
|---------------------|------------|
| `min` = `{}` | Нижние пороги: показания ниже порога заменяются NaN (строки сохраняются) |
| `max` = `{'g_minus_1': 1, 'h_minus_1': 8}` | Верхние пороги: показания выше порога заменяются NaN (строки сохраняются)[↓](#filtermax) |
| `bad_p_at_bursts_starts_period` = `''` | Период очистки импульсов давления в формате pandas (например, `'1h'`). Обнуляет первые 2 выборки за импульс для удаления артефактов запуска. Пустая строка отключает. |

Типы полей — [датакласс `ConfigFilter_InclProc`](../../src/tcm/schema.py).

### `filter.max`
Верхние границы вычисляемых на этапе обработки столбцов — значения выше
порога становятся NaN (строки сохраняются).

#### Detailed
Ключи порогов адресуют вычисляемые на этапе обработки столбцы:
`g_minus_1 = ∥Gxyz∥ − 1` (отклонение модуля гравитации),
`h_minus_1 = ∥Hxyz∥ − 1` (отклонение модуля магнитного поля);
`M` разворачивается в `Mx`/`My`/`Mz` так же, как в `input.min`/`max`.

### Calibration filter extensions (`filter/calib`)

Когда точка входа калибровки использует `filter: calib`, группа фильтров добавляет
типизированные переопределения подавления импульсов:

| Поле | Тип | Назначение |
|-------|------|---------|
| `blocks` | `List[int]` | Размеры блоков подавления импульсов Apex (по умолчанию `[21, 7]`) |
| `offsets` | `List[float]` | Пороговые значения смещения подавления импульсов Apex |
| `std_smooth_sigma` | `float` | Сигма сглаживания подавления импульсов Apex |
| `A` | `ConfigFilterChannel` | Переопределения по осям для акселерометра |
| `M` | `ConfigFilterChannel` | Переопределения по осям для магнитометра |
| `no_works_noise` | `Dict[str, float]` | Порог шума на канал |

## `metadata`

Метаданные постановки из журнала постановок приборов `info_devices.yaml`

| Поле = По умолчанию | Индексы | Назначение |
|-----------------|---------|---------|
| `point` = `?` | 0 | Идентификатор точки/станции |
| `symbol` = `?` | 3 | Символ модификации прибора (напр. `↟`) |
| `sea_depth` = `?` | 1 | Глубина моря (м) |
| `h_above` = `?` | 2 | Высота над дном (м) |
| `lat` = `?` | 4 | Широта, градусы |
| `lon` = `?` | 5 | Долгота, градусы |
| `time_range` = `?` | 6, 7 | Начало и конец корректной работы прибора на станции[↓](#metadatatime_range) |
| `burst_dt` = `?` | 8 | Длительность активной (непрерывной) записи (с) при работе с перерывами |
| `bursts_t` = `?` | 9 | Период включения (с) при работе с перерывами |
| `comment` = `?` | 10 | Комментарий |


### Detailed

[Метаданные постановки приборов `info_devices.yaml`](../user_guide/meta_finder.md#device-metadata-file) сохраняются выше каталога сырых данных, каждая запись — массив до 11-ти элементов: хвост без данных (NaN) после 8го элемента не пишется. `?, -, "", ~` эквивалентны NaN, записываются в YAML как `~`.

> В GUI элементы показаны попарно: `point, symbol | sea depth, h_above | lat, lon | time_range | burst_dt/t | comment`. Можно задать свой путь сохранения, а не тот из которого загружаются метаданные при поиске данных. `time_range` ↔ `input.time_ranges[[0,-1]]` are bidirectionally synced where unset, on scan.
>
> **Несколько интервалов постановки** (вложенная запись `info_devices.yaml` — *Multiple intervals* в [форматах meta_finder](../../../meta_finder/docs/reference/io_formats.md)) отображаются как автонумерованные подуровни **`setup`** (`0`, `1`, …), каждый подписан ключом стоянки; одиночный интервал остаётся плоским (уровень `setup` не показывается).



### `metadata.time_range`

#### Detailed
Не влияет на текущий интервал обработки - просто для записи в журнал постановки
`info_devices.yaml`.
Только при сканировании (не запуске обработки), если в конфигурационном файле `input.time_ranges` не заданы или неполное, его  недостающие концы обновляются отсюда из этой записи. Подробности — [метаданные постановок](../user_guide/meta_finder.md#tcm-gui-editor-for-metadata-records).

### `metadata.path` — показывается в GUI
Путь сохранения метаданных постановки при *`Запуске`*.

#### Detailed
По умолчанию изменения сохранятся при *`Запуске`* обсчета туда же откуда были загружены. Не меняйте путь, если хотите сохранить изменения метаданных в автозагружаемом при поиске файле: `info_devices.yaml` в том же каталоге что и каталог сырых данных (`_raw`).


### `program.return_`

#### Detailed
| Значение `return_` | Останавливается после | Типичное использование |
|:---|---|---|
| `<cfg_from_args>` | Композиция конфигурации (без ввода-вывода) | Сканирование входа, создание отсутствующих конфигураций |
| `<saved_coefs>` | Только сохранение коэффициентов | Zeroing/azimuth → сохранить коэффициенты, стоп |
| `<saved_raw>` | Сохранение сырого NC | Проверка приема сырых данных |
| `<saved_noavg>` | необработанный вывод | Диагностика без полной биннингировки |
| `<saved_all>` | Все биннированные записи NC | Пропустить комбинированный вывод |
| `<end>` (по умолчанию) | Полный пайплайн | Обычная обработка |
