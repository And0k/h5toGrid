# Справочник полей конфигурации YAML

Каждый YAML-файл запуска (`cfg_proc/run/{source_stem}.yaml`) представляет собой структурированную конфигурацию Hydra/OmegaConf.

Все поля определены в `tcm/schema.py` через класс данных `Config` и зарегистрированные группы
(`input`, `out`, `filter`, `program`).

Каждый YAML-файл запуска начинается с ``# @package _global_``, поэтому Hydra объединяет его с конфигурацией верхнего уровня.


> **Настройки поведения** (остановки по фазам, режимы коррекции времени, порядок столбцов,
> `overwrite_db`, калибровка азимута, примеры YAML) — в [config_tuning.md](config_tuning.md).
> Внутреннее устройство — в [how_it_works.md](how_it_works.md).

> **Разделы детализации полей** — Когда смысл поля зависит от контекста (обработка конкретного
> зонда vs. спецификация входных данных), ячейка таблицы остаётся лаконичной, а подробная
> документация идёт в подразделы `###` с **режимом**:
>
> | Режим | Контент | Пример потребителя |
> |-------|---------|-------------------|
> | `<mode>probe</mode>` | Смысл при обработке конкретного зонда — что делает поле, как влияет на результат | Hover в ячейках конфига GUI, во всплывающем окне |
> | `<mode>search</mode>` | Паттерны входных данных — glob, regex, директория, YAML | Поле пути GUI, справка CLI |
>
> GUI сравнивает текущий контекст с тегом `<mode>` и выбирает соответствующий контент.
> Добавляйте новые режимы как подзаголовки `### \`field.path\` <mode>value</mode>`;
> парсер распознаёт любое значение `[a-z_]+`. Ячейки таблиц — одно предложение.

### `input.path` <mode>probe</mode>

Абсолютный путь к файлу данных. Имя файла **определяет идентификатор зонда** (pcid):
пайплайн извлекает ведущую букву типа (`i` — инклинометр, `w` — волновой датчик),
необязательную букву модели (`p`, `b`, `d`) и номер зонда — напр. `i_01.txt` → pcid
`i01`, `i_p05_data.txt` → pcid `i_p05`. Неверное имя файла приводит к неверной таблице
и неверным коэффициентам.

### `input.path` <mode>search</mode>

Поддерживает glob (`*i*.txt`), regex (`i.*\.txt`) или директорию.
Суффикс `.yaml` фильтрует существующие конфигурации по стему.

#### Detailed

Верхнее поле PathField = первый позиционный аргумент CLI — якорь обнаружения
данных и конфигураций.

Допустимые формы:
- **директория** (напр. `B:\Cruises\BalticSea\`) — пайплайн ищет файлы сырых
  данных и подпапку `cfg_proc/run/`; ожидается раскладка `_raw`/`proc` (ниже).
- **glob** (`*i*.txt`) / **regex** (`i.*\.txt`) — совпадение файлов данных по имени.
- **`.yaml` путь** — загрузка готовых конфигураций напрямую, без обнаружения.

Ожидаемая структура директорий:
```
{path}\
├── _raw\            ← сырые данные (.txt/.csv/.h5/.nc) — ОБЯЗАТЕЛЬНО
├── cfg_proc\
│   └── run\         ← YAML-конфиги зондов (автогенерация при первом сканировании)
├── proc\            ← NC-результаты пайплайна (создаётся при Run)
└── text_output\     ← TSV-экспорт (создаётся при Run)
```

Типичные ошибки:
- `FileNotFoundError: не найдено входных файлов, соответствующих …` — `_raw` отсутствует или
пусто; укажите **корневую** директорию экспедиции, а не конечную точку.
- `SystemExit` из `_print_usage_error` — путь не найден; проверьте, что он абсолютный.

### `input.coefs_path` <mode>dir</mode>
Выберите каталог с файлами коэффициентов для каждого зонда. Программа сама выберет в нем файл `{tbl}.yaml` по идентификатору зонда (примеры `tbl`: `incl03`, `incl_p05`, `incl_b12`). Каждый файл YAML
должен соответствовать структуре `input.coefs` и содержать как минимум одно калибровочное поле (`Ag`, `Cg`, `Ah`, `Ch`, `Rz`, `kVabs`, `azimuth_shift_deg`).

Отсутствует файл зонда → автоматическое переключение на зашитые значения по умолчанию.
Прилагаемые коэффициенты в человекочитаемом (YAML) формате см. в директории `cfg/coef/yaml_export/`.

### `input.coefs_path` <mode>file</mode>
Единый исходный файл коэффициентов: HDF5 (`.h5`), NetCDF4 (`.nc`) или
экспортированный YAML (`.yaml`). yaml - задает одни и теже коэффициенты для всех зондов, HDF5/NetCDF - выбираются из групп соотвтетсвующих индетификатором зондов (аналогично наименованию таблиц сырых данных). Допускаются пути, разделенные запятыми (цепочка резервных вариантов, побеждает первое наличие/совпадение).

## `input.coefs` — Калибровочные коэффициенты
Загружается из файла коэффициентов и копируется в каждый YAML-файл для каждого зонда при первом запуске.
Редактируйте их, чтобы обновить калибровку зонда — изменения сохраняются автоматически.


| Поле        | Тип        | По умолчанию                            | Физический смысл |
|-------------|------------|-----------------------------------------|------------------|
| `Ag`        | 3×3 float  | `[[1.73e-3,0,0],[0,1.73e-3,0],[0,0,1.73e-3]]` | Матрица масштаба акселерометра: `G = Ag · (Axyz − Cg)` |
| `Cg`        | 3-float    | `[10, 10, 10]`                          | Вектор смещения акселерометра |
| `Ah`        | 3×3 float  | Единичная                               | Матрица масштаба магнитометра: `H = Ah · (Mxyz − Ch)` |
| `Ch`        | 3-float    | `[10, 10, 10]`                          | Вектор смещения магнитометра |
| `Rz`        | 3×3 float  | Единичная                               | Ротация совмещения датчика и прибора, применяемая после калибровки |
| `kVabs`     | 6-float    | `[10, −10, −10, −3, 3, 70]`            | Полином скорости: `Vabs(наклон)` |
| `P`         | 2-float    | `[0, 1]`                                | Линейная коррекция вспомогательного датчика №1: `y = P[0] + P[1]·x` |
| `PBattery`  | 2-float    | `[0, 1]`                                | Линейная коррекция напряжения батареи |
| `PTemp`     | 2-float    | `[0, 1]`                                | Линейная коррекция температуры |
| `azimuth_shift_deg` | `float` | `180`                            | Поправка азимута (градусы) — переводит направление наклона из датчика в географические координаты. По умолчанию `180°` компенсирует инверсию знака магнитометра при загрузке. См. [Калибровка азимута](config_tuning.md#azimuth-calibration). |
| `g0xyz`     | 3-float    | `None`                                  | Пользовательский вектор эталона гравитации. При задании перекрывает `Rz` вычисленной ротацией. |
| `dates`     | `Dict[str, str]` | `{}`                              | Даты калибровки по компонентам |
| `date`      | `str`      | `None`                                  | Общая дата калибровки |

Датчики давления (тип `p`) используют `P_t` (2D полином) вместо тройки скаляров
`P`/`PBattery`/`PTemp`. При наличии `P_t` эти скаляры игнорируются.

## `filter` — Пороги контроля качества на этапе обработки

`filter` — это **этап обработки**: значения, превышающие пороговые значения, становятся NaN (строки
**сохраняются**, а не удаляются). В отличие от `input.min`/`max` — **этап загрузки DROP**,
который удаляет целые строки. Одни и те же имена ключей могут встречаться в обоих пространствах имен с
разной семантикой.

| Поле | Тип | По умолчанию | Назначение |
|-------|------|---------|---------|
| `min` | `Dict[str, float]` | `{}` | Нижние границы: значения с `\|col\| < min[col]` установлены в NaN. |
| `max` | `Dict[str, float]` | `{'g_minus_1': 1, 'h_minus_1': 8}` | Верхние границы. `M` разворачивается в `Mx`/`My`/`Mz`. |
| `bad_p_at_bursts_starts_period` | `str` | `''` | Период очистки импульсов давления (например, `'1h'`). Обнуляет первые 2 выборки за импульс для удаления артефактов запуска. Пустота отключает. |


`g_minus_1 = ∥Gxyz∥ − 1` (отклонение модуля гравитации),
`h_minus_1 = ∥Hxyz∥ − 1` (отклонение модуля магнитного поля).

### Calibration filter extensions (`filter/calib`)

Когда точка входа калибровки использует `filter: calib`, группа фильтров добавляет
типизированные переопределения подавления импульсов:

| Поле | Тип | Назначение |
|-------|------|---------|
| `blocks` | `List[int]` | Размеры блоков подавления импульсов Apex (по умолчанию `[21, 7]`) |
| `offsets` | `List[float]` | Пороговые значения смещения подавления импульсов Apex |
| `std_smooth_sigma` | `float` | Сигма сглаживания подавления импульсов Apex |
| `A` | `ConfigFilterChannel` | Переопределения по осям для акселерометра |
| `M` | `ConfigFilterChannel` | Переопределения по осям для магнитометра |
| `no_works_noise` | `Dict[str, float]` | Порог шума на канал |


## `proc` — Параметры обработки по точке входа (опционально)
`proc` — это **необязательная** группа для каждой точки входа. Для точки входа обработки групп нет.

| Точка входа | Опция `proc` | Класс данных | Назначение |
|-------------|--------------|-----------|---------|
| Обработка | *(none)* | — | Все параметры обработки находятся в `out.dt_bins` + `input.calc_version` |
| Калибровка | `calib` | `ConfigProcCalib` | Сопоставляется с полями `PipelineConfig` |
| Спектр | `spectrum` | `ConfigProcSpectrum` | **Зарезервировано** — модуль spectrum еще не портирован |


## `program` — Параметры запуска

| Поле | Тип | По умолчанию | Назначение |
|-------|------|---------|---------|
| `return_` | `str` | `'<end>'` | Точка выхода из конвейера. Выполнить частичную обработку для отладки (например, `'<saved_raw>'` для проверки приема данных). См. [фаза завершения](config_tuning.md#phase-stopping). |
| `dask_scheduler` | `str` | `''` | Бэкенд выполнения Dask: `'synchronous'` для отладки, `'threads'` для производственной среды. |
| `sleep_s` | `float` | `0.5` | Пауза (секунды) между проверками. Увеличьте, если во время выполнения нескольких проверок возникает высокая нагрузка на память. |
| `verbose` | `str` | `'INFO'` | Подробный вывод логов консоли. `DEBUG` для устранения неполадок, `INFO` для обычных запусков. |
| `use_h5` | `str` | `'auto'` | Политика двоичного ввода-вывода. `auto` = использовать, если доступно, пропускать без уведомления. `off` = отключить NC/HDF5. `require` = ошибка, если недоступно. `prefer` = предупреждение и резервный вариант. |
