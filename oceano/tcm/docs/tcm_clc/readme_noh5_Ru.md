# tcm_clc — Обработка данных инклинометров

CLI-утилита для обработки данных инклинометрических съёмок: из сырых CSV-файлов
вычисляются скорость, наклон, направление и давление.

Версия "noh5": `tcm_clc_txt` не требует HDF5-библиотек (h5py, pytables) —
все данные читаются из и результаты сохраняются в текстовые файлы.

## Быстрый старт

```bash
# Обработка всех "i*.txt" в каталоге данных "_raw"
tcm_clc_txt.exe "_raw"

# Обработка конкретных датчиков
tcm_clc_txt.exe "_raw/*i*.txt" input.ids=[i01,i_p02]

# Переопределение параметров (см. config_reference.md)
tcm_clc_txt.exe "_raw/*i*.txt" filter.corr_time_mode=false out.text_path=./results
```

Первый позиционный аргумент — **путь для сканирования**: каталог, glob или regex.
Простой каталог сканирует `i*.txt` (без учёта регистра). Формат строки поиска файлов - glob, если не используется экранированная точка, иначе — regex (напр. `i.\\.txt`; см. `_pattern_to_regex` в `docs/tcm_clc/how_it_works.md`). Имя `_raw` — лишь рекомендуемое, можно
загружать из любого места, если в пути есть _raw, то обработанные данные сохраняются на уровень выше.

### Типичные сценарии

**Первый запуск на новых данных**:
При первом запуске программа создаёт каталог `cfg_proc/` внутри `_raw/` и
автоматически генерирует конфигурационные YAML-файлы для каждого датчика
в `cfg_proc/run/`. Отредактируйте коэффициенты и повторите запуск:

```bash
# Этап 1: сгенерировать конфигурации (автоопределение из данных)
tcm_clc_txt.exe "_raw/i*.txt"

# Отредактировать cfg_proc/run/@i_01.yaml — заменить коэффициенты по умолчанию
# на реальные значения, затем повторить:
tcm_clc_txt.exe "_raw/i*.txt"
```

**Повторная обработка с изменёнными настройками**: отредактируйте YAML датчика,
запустите заново.

## Обзор конвейера

Конвейер обрабатывает сырые данные датчиков в три этапа:

1. **Обнаружение и генерация конфигураций** — сканирует каталог сырых данных,
  и генерирует соответствующие YAML-конфигурации: для этого из названия файла
  определяет стандартизированный идентификатор датчика (pcid) и остальные части (см. часть по YAML ниже). В нем устанавливает пределы фильтрации input.time_ranges (подробнее см. config_reference.md)
  по временному диапазону из содержимого файла (что облегчает редактирование пределов), вставляет найденные из поставляемых с программой калибровочных файлов коэффициенты (если они есть для идентификатора, иначе - шаблонные значения).
  Конфигурации сохраняются между запусками — только добавляются новые, соответствующие новым файлам исходных данных. Если конфигурации уже есть, то в них добавляет input.time_ranges, если не было.

2. **Загрузка и подготовка** — загружает сырые данные, применяет калибровочные
  коэффициенты согласно приоритету (см. ниже, приоритет сохраненных YAML — максимальный), применяет азимутальную коррекцию и выравнивание (zeroing) если указано (напр. временные окна - см. config_reference.md) .

3. **Обработка и экспорт** — вычисляет проекции скорости (`u`, `v`),
  абсолютную скорость (`Vabs`), направление (`Vdir`), давление, наклон датчика.
  Усреднение по настраиваемым интервалам (по умолчанию в дистрибутиве:
  без усреднения и 1 ч).
  Сохраняет в TSV-файлы.

## Выходные файлы

```text
data_dir/_raw/ ← каталог сырых данных (соглашение: _raw; может быть любое имя)
    i_01.txt   ← исходный
    @i_01.txt  ← исправленный (генерируется автоматически, если нечего исправлять - совпадает с i_01.txt)
    cfg_proc/           ← каталог конфигураций Hydra (создаётся внутри _raw/)
        run/            ← конфигурации датчиков (коэффициенты, диапазоны)
            @i_01.yaml  — редактируйте этот файл
        log/            ← журналы программы
    text_output/        ← результаты (*.TSV, это расположение по умолчанию)
```

| Файл | Содержимое |
|------|-----------|
| `text_output/{timestamp}@{pcid}.tsv` | Текстовые таблицы без усреднения |
| `text_output/{timestamp}bin3600s@{pcid}.tsv` | Текстовые таблицы, усреднение 1 час |

## Идентификатор датчика (pcid)

Каждый датчик идентифицируется строкой `pcid`, которая связывает сырые данные,
коэффициенты, конфигурацию и выходные файлы:

- `i01` — инклинометр №01
- `i_p02` — инклинометр модели p, №02
- `w01` —  датчик давления (волнения) №01

`pcid` отображается в имя YAML-конфигурации (`@i_01`), имя файла сырых данных.
При сохранении в netCDF4/HDF5 - в имя таблицы (`incl01`), при сохранении нескольких датчиков в одной таблице или файле - в имя колонки.

## Конфигурация

Четыре группы конфигурации управляют поведением конвейера. Любое поле можно
переопределить через командную строку или в YAML-файле датчика:

| Группа | Назначение | Основные поля |
|--------|-----------|---------------|
| `input` | Исходные файлы, калибровка, диапазоны | `path`, `ids`, `coefs`, `time_ranges`, `coordinates` |
| `out` | Формат вывода, усреднение, экспорт | `dt_bins`, `text_path`, `split_period` |
| `filter` | Пороги качества данных | `min`, `max`, `corr_time_mode` |
| `program` | Поведение программы | `return_`, `verbose`, `use_h5` |

`use_h5` (необязательно): управление HDF5/netCDF операциями ввода-вывода.
`None` (по умолчанию) — автоопределяет наличие библиотек. В noh5-сборке
автоматически отключается, что подавляет попытки сохранения в NC/HDF5.
`True` — принудительно включить (ошибка, если библиотеки недоступны).
`False` — принудительно отключить с предупреждениями о пропущенных операциях.
Полный справочник полей: `docs/tcm_clc/config_reference.md`.

### YAML-конфигурации датчиков

Конфигурация каждого датчика находится в
`cfg_proc/run/{префикс}@{pcid}-{комментарий}.yaml`.

- `{префикс}` (например `260624_1730`) генерируется автоматически из первой
  временной метки данных в формате `%y%m%d_%H%M`. Если на момент генерации
  временные метки отсутствуют (редко), файл создаётся без префикса: `@{pcid}.yaml`.
- Всё до **последнего** `@` — метаданные, для идентификации датчика игнорируются.
  Суффикс `-{комментарий}` после pcid-stem также отбрасывается
  (см. `tcm.format.stem_to_pcid`).
- Так `@i_01.yaml`, `260624_1730@i_01.yaml`, `@i_01-extra.yaml` определяют
  один датчик `i01`.

Конфигурации генерируются автоматически при обнаружении новых файлов и **не
перезаписываются** при последующих запусках — только добавляются отсутствующие
или пересоздаются устаревшие (ссылающиеся на удалённый файл). Поэтому:

- **`input.path` — это реальная связь** между YAML и исходным файлом данных.
  Имя YAML-файла (`{дата}@{стем}.yaml`) — только метаданные; конвейер
  использует `input.path` для доступа к данным, а не имя файла.
- **Переименование YAML-файла** создаёт **дубликат** для одного датчика → конвейер
  обрабатывает каждый YAML независимо. Данные не дублируются: выходной NC
  использует инкрементальное добавление (перекрывающиеся диапазоны пропускаются),
  но коэффициенты записываются дважды (последний YAML побеждает). Удалите
  устаревшую копию, чтобы избежать лишней работы.
- **Устаревшие конфигурации** (чьи `input.path` ссылаются на удалённый файл)
  только предупреждаются, но **не удаляются автоматически**.  При переименовании
  или перемещении исходного файла старый YAML становится устаревшим, а новый
  генерируется — старый остаётся и должен быть удалён вручную.
- **Дедупликация**: при перегенерации конфигураций конвейер проверяет, есть ли
  уже YAML для того же нормализованного pcid с существующим `input.path`.
  Если да — новый YAML не создаётся.  Это предотвращает дубликаты, когда один
  датчик имеет файлы с разным форматированием имени (напр. `i_090` и `i90`).
- **Только генерация конфигураций** (без обработки данных):
  `tcm_clc_txt.exe "_raw/i*.txt" 'program.return_="<cfg_from_args>"'`.

Содержимое можно редактировать вручную:

```yaml
# @package _global_
input:
  path: "/abs/path/to/@i_01.txt"
  coefs:
    Ag: [[0.00173,0,0],[0,0.00173,0],[0,0,0.00173]]
    Cg: [10,10,10]
  time_ranges: ["2023-01-15T10:00:00", "2023-01-15T14:30:00"]
out:
  dt_bins: [0, 3600]
  text_path: "text_output"
```

Обычные действия: заменить коэффициенты по умолчанию на реальные значения
калибровки, сузить `time_ranges` до периода развёртывания, указать `coordinates`
для коррекции магнитного склонения.

## Калибровочные коэффициенты

> **Подгонка эллипсоида** (вывод новых коэффициентов из сырых данных)
> выполняется пакетом `calibration/` (`run.py` → `run_calibration`) и требует
> **полной** среды (scipy, matplotlib, h5py). Версия "noh5" их не содержит —
> коэффициенты задаются вручную в YAML. Подробности: `docs/calibration/calibration_wiki.md`.

### Приоритет разрешения коэффициентов (от высшего к низшему):

1. `input.coefs` в YAML-файле датчика — редактируйте здесь для конкретного датчика
2. `coefs_path` — общий HDF5 или YAML-файл коэффициентов (по умолчанию не используется в "noh5" поставке, т.к. указан отсутствующий в поставке HDF5-файл)
3. Каталог `tcm/cfg/coef/yaml_export/` (калибровки в текстовом виде, поставляемые с пакетом)
4. Шаблонные значения в коде программы (одинаковые на все датчики)

### Поставляемые файлы коэффициентов (`yaml_export/`)

Коэффициенты каждого датчика хранятся в YAML-файле, названном по **имени таблицы**
(производится из `pcid` через `pcid_to_raw_name()`):

| pcid | Имя таблицы | Файл коэффициентов |
|------|------------|-------------------|
| `i01` | `incl01` | `yaml_export/incl01.yaml` |
| `i_p05` | `incl_p05` | `yaml_export/incl_p05.yaml` |
| `i_b03` | `incl_b03` | `yaml_export/incl_b03.yaml` |

Для редактирования: откройте YAML, измените значения в секции `input.coefs`,
сохраните. Структура YAML совпадает с форматом конфигурации датчика — можно
копировать блоки коэффициентов непосредственно в `cfg_proc/run/@i_XX.yaml`.

### Обновление коэффициентов через выравнивание (zeroing) наклона и азимута

Две независимые операции, каждая со своим временным окном:

| Параметр | Что | Как | Записывается в |
|----------|-----|-----|---------------|
| `time_ranges_zeroing` | Поворот по вертикали (наклон) | `orientation.zeroing_rotation()` по данным акселерометра | `Rz` |
| `time_ranges_azimuth` | Направление наклона (азимут) | `orientation.azimuth_shift()` по единичным векторам маг+акс | `azimuth_shift_deg` |

Вычисление азимута использует только единичные векторы (без зависимости от
``kVabs`` или коэффициентов пересчёта наклона в magnitude).

Если также указаны `azimuth_add` или `coordinates`, их коррекции применяются
**поверх** вычисленного по данным азимута (например, ручное смещение или
магнитное склонение).

**Куда сохраняются обновлённые коэффициенты** (в версии noh5 — в YAML):

| Источник | Куда сохраняется |
|----------|-----------------|
| CSV/TXT (noh5) | YAML-файл запуска (`cfg_proc/run/@i_01.yaml`, секция `input.coefs`) |


#### Типичный сценарий выравнивания

```bash
tcm_clc_txt.exe "_raw" \
  'input.time_ranges_zeroing=["2026-06-25T17:23:30","2026-06-25T17:25:00"]' \
  'input.time_ranges=["2026-06-25T17:23:30","2026-06-25T17:25:00"]'
```

Для сохранения коэффициентов без полной обработки добавьте
`'program.return_="<saved_coefs>"'` (коэффициенты запишутся в YAML с резервной
копией). Для сохранения коэффициентов + сырых данных используйте
`'program.return_="<saved_raw>"'`.

##### Выравнивание через `g0xyz`

Вместо вычисления `Rz` из интервала данных можно указать `g0xyz` — вектор
акселерометра `[Ax, Ay, Az]`, измеренный при нулевом наклоне (например, на отвесе).
Конвейер вычисляет матрицу поворота, отображающую этот вектор на вертикаль:

```yaml
input:
  coefs:
    g0xyz: [100.5, 50.2, 980.1]   # сырые показания акселерометра при нулевом наклоне
```

При указании `g0xyz` он **заменяет** любое существующее `Rz` в коэффициентах.

| Метод | Входные данные | Что вычисляет | Типичное применение |
|-------|---------------|---------------|-------------------|
| `g0xyz` | Один вектор акселерометра при известном нулевом наклоне | Поворот для совмещения оси Z датчика с гравитацией | Лабораторная калибровка, эталонный отвес |
| `time_ranges_zeroing` | Интервал данных с неподвижным прибором | Средний поворот по нескольким выборкам | Полевое выравнивание, коррекция после развёртывания |

Если указаны оба, `g0xyz` имеет приоритет.


#### Типичный сценарий калибровки азимута

1. Разверните прибор на известном азимуте (например, по компасу на Север).
2. Запишите данные в этом положении 1–2 минуты.
3. Укажите интервал в YAML: `input.time_ranges_azimuth: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]`.
4. Запустите конвейер — `azimuth_shift_deg` вычислится и запишется в YAML.

Для расчёта азимута нужны *Калиброванные* коэффициенты:
- `Ah`, `Ch` (магнитометр) и `Ag`, `Cg` (акселерометр): должны быть загружены из YAML `yaml_export/` или заданы вручную в  **до** запуска.
- `Rz` (калировка наклона), или если ещё не вычислена, можно вместо нее указать `time_ranges_zeroing` или `g0xyz` — она обновится первой, затем азимут использует уже выровненные векторы.


### Калибровка азимута (направления наклона)

`azimuth_shift_deg` — поправка, переводящая **направление наклона** (азимут
наклона прибора) из системы координат датчика в географические координаты.
По умолчанию `180°` — компенсирует инверсию знака магнитометра при загрузке
(``invert_magnetometer`` в ``csv_load.py`` → ``Mxyz`` инвертируется в ``format_loaded.py``).

Физический смысл: инклинометр измеряет не курс корпуса, а **азимут направления
наклона** — откуда идёт течение. Магнитометр определяет где Север,
акселерометр — плоскость наклона. Формула `Vdir` использует векторное
произведение `G × H` (гравитация × магнитное поле) для определения
направления наклона в сенсорных координатах, затем `azimuth_shift_deg`
переводит результат в градусы от Севера.

#### Порядок действий

Полная калибровка (из `scripts/26xx_calibr_incl_hy.py`):

1. **Лаборатория** (подгонка эллипсоида) — требует **полной среды** (scipy, h5py):
   запустите `calibration.run.run_calibration` на данных магнитометра и
   акселерометра → получите `Ag, Cg, Ah, Ch`. В noh5-версии эти коэффициенты
   задаются вручную в YAML из `yaml_export/`.

2. **Выравнивание наклона** (`time_ranges_zeroing`) — прибор подвешен отвесно,
   записаны данные → вычисляется `Rz` (матрица поворота для совмещения оси Z
   датчика с гравитацией).

3. **Калибровка скорости** (в бассейне/на стенде) — определяет `kVabs`
   (полином пересчёта наклона в скорость).

4. **Калибровка азимута** (`time_ranges_azimuth`) — прибор наклонён в
   **известном направлении** (например, известно что наклон на Север),
   записаны данные. Конвейер вычисляет азимут сдвига и записывает
   `azimuth_shift_deg` в YAML.

#### Настройка через YAML

```yaml
# Все калибровки одновременно:
input:
  time_ranges_zeroing: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]   # Rz
  time_ranges_azimuth: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]   # azimuth_shift_deg
  time_ranges: ["2026-06-25T17:23:30", "2026-06-25T17:25:00"]           # фильтрация данных
  coefs:
    azimuth_shift_deg: 180   # по умолчанию (компенсация invert_magnetometer)
```

**Поправки поверх вычисленного азимута:**
- `azimuth_add` — ручное смещение (градусы)
- `coordinates` + `data_date` — магнитное склонение (через `pygeomag`)

## Требования к исходным данным

### Имена файлов → коэффициенты

Конвейер определяет `pcid` датчика по имени файла, затем сопоставляет с именем
таблицы, которое выбирает файл коэффициентов. **Неправильное имя файла →
неправильная таблица → неправильные коэффициенты.**

| Имя файла | pcid | Таблица | Файл коэффициентов |
|-----------|------|---------|-------------------|
| `i_01.txt` | `i01` | `incl01` | `incl01.yaml` |
| `i_p05.txt` | `i_p05` | `incl_p05` | `incl_p05.yaml` |
| `INKL_P05_0_v_trube.TXT` | `i_p05` | `incl_p05` | `incl_p05.yaml` |
| `incl_b03.txt` | `i_b03` | `incl_b03` | `incl_b03.yaml` |
| `I_P01_001.txt` | `i_p01` | `incl_p01` | `incl_p01.yaml` |
| `w01.txt` | `w01` | `w01` | — |

Правила сопоставления (реализованы в `tcm/format.py`):
1. Ведущие неалфавитные символы и общие префиксы (`INKL_`, `INCL_` и т.д.) удаляются
2. Тип датчика: `i` = инклинометр, `w` = датчик волнения
3. Буква модели после типа: `p`, `b`, `d` (или отсутствует для простых инклинометров)
4. Номер датчика: ведущие нули удаляются
5. Имя таблицы = `incl` + модель + номер (напр. `i_p05` → `incl_p05`)

Исправленные файлы (с префиксом `@`) сопоставляются идентично — `@i_01.txt` и
`i_01.txt` определяются как один датчик.

**Проверка**: запустите с `program.return_="<cfg_from_args>"` чтобы увидеть,
какой pcid/таблицу присваивает конвейер, без обработки данных:

```bash
tcm_clc_txt.exe "_raw/*i*.txt" 'program.return_="<cfg_from_args>"'
```

В журнале появится: `Coefs for i_p05: paths=[...], date=2023-08-13` —
подтверждение идентификатора датчика и загруженного файла коэффициентов.

### Обязательные столбцы

Сырые CSV/TXT-файлы должны содержать как минимум (заголовок определяется
автоматически):

| Тип датчика | `text_type` | Обязательные столбцы | Необязательные |
|-------------|:-----------:|---------------------|---------------|
| Инклинометр | `i`, `b` | `Ax, Ay, Az, Mx, My, Mz` | `Battery, Temp` |
| Давление | `p`, `d` | `Ax, Ay, Az, Mx, My, Mz, P_counts` | `Battery, Temp` |
| Давление (исп. раньше только для опр. волнения) | `w` | `Battery, Temp` | — |

При нестандартном заголовке переопределите автоопределение через `input.text_type`.

## Сообщения в консоли и журнале

При обработке конвейер выводит информационные сообщения о статусе коэффициентов.
Ключевые сообщения:

| Сообщение | Значение |
|-----------|---------|
| `Coefs for i_p05: paths=[...], date=2023-08-13` | Коэффициенты загружены; `paths` показывает цепочку источников |
| `Loaded 3 new coefs from yaml_export/incl_p05.yaml: [Ag, Cg, kVabs]` | Новые коэффициенты загружены из файла |
| `All coefs from ... already in overrides` | Пользовательские переопределения уже содержат все коэффициенты |
| `Coefs prepared: with new rotation to direction averaged on configured time_ranges_zeroing interval` | Вычислена матрица поворота из интервала данных |
| `Coefs prepared: with new rotation to user defined zero point (g0xyz)` | Матрица поворота из эталонного вектора `g0xyz` |
| `Coefs unchanged for i_p05 — skipping write` | Коэффициенты не изменились; ничего не записано |
| `Updated coefs [Rz] in @i_p05.yaml` | Изменённые коэффициенты записаны в YAML |
| `Updated coefs [azimuth_shift_deg] in @i_p05.yaml` | Поправка направления наклона записана в YAML |
| `Coefs saved to ...//incl_p05: 12 datasets` | Коэффициенты записаны в NC-файл |
| `Zeroing data -> no-op: time_ranges_zeroing ... not in current data range` | Предупреждение: в указанном интервале нет данных |
| `Azimuth data -> no-op: time_ranges_azimuth ... not in current data range` | Предупреждение: в интервале азимута нет данных |

Расположение журнала: `cfg_proc/log/{timestamp}/tcm_clc.log` (внутри каталога данных).
